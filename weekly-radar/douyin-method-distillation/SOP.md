# 单条抖音视频方法蒸馏 SOP

适用范围：用户已授权、已登录账号“喜欢”页中目标作者的视频。原视频只用于本地研究，不重新发布，不放进 Git。

## 1. 队列取数

1. 打开登录态浏览器的喜欢页。
2. 只记录页面中显示作者为目标作者的视频；以 `videoId` 去重。
3. 新条目追加到 `queue.json`，初始阶段为 `queued`。作者合集里存在但喜欢页未出现的视频不加入。

## 2. 浏览器下载

1. 打开队列中的视频详情页并开始播放，让浏览器插件捕获媒体资源。
2. 优先使用 CocoCut。抖音可能把画面和声音分成两条 MP4：不能按文件大小猜，必须分别用 `ffprobe` 检查流类型。
3. 保留浏览器下载的原文件；将画面轨和音轨路径传给处理脚本。脚本会复制文件，不移动、不覆盖原下载。

示例：

```bash
npm run research:douyin-method -- \
  --video-id 7664884994812432869 \
  --video '/absolute/path/to/video-only.mp4' \
  --audio '/absolute/path/to/audio-only.mp4'
```

如果一个文件本身同时含画面和声音，只传 `--video`。

先检查但不落盘：

```bash
npm run research:douyin-method -- \
  --video-id 7664884994812432869 \
  --video '/absolute/path/to/file.mp4' \
  --dry-run
```

## 3. 脚本处理

脚本按以下顺序执行：

1. 核对 `queue.json` 中存在该 `videoId`。
2. 用 `ffprobe` 判断流类型；需要时无重编码合并画面和声音。
3. 用 FFmpeg 完整解码，失败则不推进队列状态。
4. 计算 SHA-256，写入 `metadata.json` 和 `probe.json`。
5. 每 20 秒生成一张抽帧总览。
6. 默认使用本机 `mlx-whisper` 生成 TXT、SRT、VTT、TSV、JSON 转写。
7. 生成 `method-notes.md` 模板，并把队列阶段推进到 `transcribed`；`--skip-transcribe` 时只推进到 `media_ready`。

所有运行结果进入：

```text
weekly-radar/.local/douyin-method-distillation/<author-slug>/<videoId>/<vNN>/
```

脚本拒绝覆盖已经存在的版本目录。需要重跑时显式传新版本，例如 `--version v02`。

## 4. 人工证据校正

1. 通读带时间戳的转写，标记明显错词、重复和幻听区间。
2. 查看抽帧总览，并在方法节点附近补抽原分辨率关键画面。
3. 至少交叉核对“口述 + 画面 UI/示例”；评论区只能作线索，不能替代视频证据。
4. 转写异常区间不得用于方法结论；在 `metadata.json` 和笔记中明确记录。

## 5. 方法蒸馏

`method-notes.md` 至少包含：

- 一句话核心结论；
- 作者实际演示的步骤及时间范围；
- 可迁移的提示词原则；
- 明确标注的归纳模板（不得冒充作者逐字原句）；
- 工具版本、推广内容、缺少 A/B 对照等限制；
- 所用转写和画面证据文件。

只有上述内容完成并复核后，才把队列阶段改为 `distilled`。

字数、格式、时间标题、转写链接和脚本成功只能证明文件结构，不能代替逐条来源核对。脚本不得用固定创作内容覆盖旧稿，或自动声称“媒体、转写、画面已复核”。纠正已存在的笔记时保留旧稿，使用新的 `vNN` 资料版本并在队列说明当前阅读入口；不得为了重写笔记重新下载已验证媒体。

## 6. 接入制作方法

1. 先分清作者主张、可观察事实、本地推导与未验证效果。声音效果须实际试听，连续动作须连续播放；ASR 与抽帧不能代替。
2. 把可信要点归到已有的剧情、素材或分镜问题域，写明“何时用、想让观众感到什么、具体怎么表达、写到哪里、何时不用”。不按每条视频新建 Skill，不把教程固定时长或平台操作升级为通用规则。
3. 由 AI Director 在 [剧情驱动的技巧选择](../../director-knowledge-base/分镜提示词/剧情驱动的技巧选择.md) 调用主题方法；来源笔记作为证据，用户和当前项目事实优先。只有明确请求长期流程变化时才更新对应 SOP／Skill，不替用户改项目或触发生产。
4. 在当前分镜的实际行动、摄影、声音或剪辑中体现方法。授权试片后根据真实观察修正；记录“本次有效”的范围，不把单次成功或结构校验称为跨模型验证。

## 7. 轮询方式

后续轮询分两步：

1. 在登录态喜欢页滚动到底，按作者名提取当前 `videoId` 集合，与 `queue.json` 比较后只追加新增项。
2. 依次处理 `queued` 或 `blocked` 条目。浏览器登录态和 CocoCut 下载仍是浏览器侧步骤；下载后的合并、校验、转写、归档与状态更新由脚本完成。

未经用户另行确认，不批量抓取作者主页/合集里的未点赞视频。
