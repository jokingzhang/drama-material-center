# 和用户一起设计分镜

用于新场次、新分镜或重大重设计中尚未确定的导演选择。采用用户要求的 `grill-me / grilling` 交互：先查已有资料，沿决策依赖逐个追问，每次只讨论一个关键问题，并给出推荐。这里的目标是共同形成更好的观看体验，不是让用户替导演填写摄影参数。

## 什么时候讨论，什么时候直接做

- 用户要求“聊聊怎么拍、一起设计、像 grill-me 一样讨论”：先讨论，再在已授权范围内写作。
- 新分镜或重大重设计：读取当前剧本与用户决定后，若存在会明显改变观众理解、人物关系或情绪落点的未定选择，默认开启讨论；不要先写完整稿再让用户整份推翻。
- 方向已经清楚，或用户说“直接写、你来决定”：说明有影响的假设并继续，不强制问答轮数，不重新确认已有选择。
- 局部修补、已定方案落提示词、上传与恢复：直接做对应工作。只有新发现的上游矛盾影响当前结果，才重开那个选择。
- 只要求分析时不修改项目。创意讨论不等于关键帧审核、付费生成或外部写入授权。

## 每轮怎样问

先从资料判断：这场发生了什么，谁想得到什么，谁作出选择，关系从什么状态变成什么状态；哪些事实和对白不能改。文件能回答的先读文件，不让用户重复讲。

按依赖选择**此刻最值得回答的一个问题**，不是固定逐项问完：

1. 事件、人物选择或关系变化不清楚，先解决它；不靠运镜补一个没有因果的故事。
2. 故事已定，决定观众跟谁看、何时知道关键信息、最终留下什么感受。
3. 再比较承载它的视点、表演、节奏、声音及切点。只有取舍确实明显，才向用户展开摄影形式或生产成本。

一轮用简短自然语言完成：

- 指出当前剧情里真正的分歧，给出自己的推荐及其观看效果。
- 有用时给一个对照方向，说明得到什么、损失什么；不默认列四套方案。
- 提出一个问题，然后等待回答。不要在同轮附带画幅、时长、焦段、音乐、镜头数等多项问卷；推荐不等于用户已选择。

例如（虚构剧情，仅示范讨论）：

> 我建议先让观众看清林遥的湿肩和推伞动作，而周宁暂时没有留意。这样观众会比周宁早一点读懂关心，甜感来自“装作顺手”。如果先不露湿肩，等周宁回头时一起发现，惊喜更强，但前面的克制会少一些。你更希望观众提前心领神会，还是跟周宁一起发现？

不要问“用微表情 Skill 还是长镜头 Skill”。用户选的是戏；方法由导演根据选择调用。也不要把没有剧本依据的秘密、伤病或牺牲写进选项，诱导用户被迫接受新剧情。

## 回答和新信息怎样进入作品

收到回复，先用一句话说明它改变了什么，再继续下一个确有必要的问题，或开始写作。新信息覆盖冲突的旧假设，不自动推翻未受影响的工作。

| 新信息类型 | 更新范围 |
| --- | --- |
| 本场事实、人物意图、对白或希望观众感到什么 | 现有剧本／分镜中受影响的设计与下游正文；改对白先按 Writer 更新事实源 |
| 本次制作约束，如不加素材、保留已通过镜头、限定时长 | 当前方案及实际受影响的输入、接镜和执行计划 |
| “以后都这样”“把这个写进 SOP／Skill”等明确长期工作方式 | 在授权内更新承担该规则的 SOP／Skill；通用创作方法进入知识库，单剧事实留在项目规则；不自动改个人记忆 |
| 教程、案例或效果建议 | 先区分来源事实、作者主张、本地推导和未验证效果，再按知识维护规则判断是否纳入 |

在现有分镜的“导演设计／剧情作用”或当前工作记录保留必要决定即可。例如“观众先知道关心，周宁后发现；以推伞动作和湿肩反应承载”。不新增问答档案、冻结表、逐镜方法账本或审核层。

写作时沿着 [剧情驱动的技巧选择](../../../../director-knowledge-base/分镜提示词/剧情驱动的技巧选择.md) 把选择落实到真实的行动、取景、声音和接点；不能只在设计说明里说“克制”，正文却仍是泛泛的“深情凝望”。

## 什么时候结束讨论

当本次交付所需的故事目的、观看顺序和关键取舍足以支持写作，就简短收束并继续已授权工作。不要求所有摄影维度都问一遍，也不在方案、正文、审查之间重复索取同一确认。用户的新回复可以随时修正后续设计；已经人工接受的媒体继续受原用途与返修边界保护。
