# 人物外形设计

由当前主会话执行，作为 [AI Director](../ai-director/SKILL.md) 的美术方法，也可独立处理已明确的人物任务。把角色区别落实到可见的结构和造型，形成可供后续镜头复用的人物标准图；不增加作者、子代理或审批阶段。

## 从当前人物事实开始

先按 [制作 SOP](../../../PRODUCTION_SOP.md) 恢复当前任务范围，读取目标项目的剧本人物设定、项目规则、正式绑定和已有图像。复用上下文中已检查且未变化的内容。区分新人物、同一人物的新造型与既有图的局部返修；角色全名、`characterId`、`lookId`、年龄阶段、世界观和用户已选外形是当前事实。

- 新人物：在授权范围内提出外形候选，缺少会改变人物身份或故事含义的事实时先定位问题；普通美术细节可合理设计并标为候选，不让用户填写整套参数表。
- 换装或换状态：保留已确认脸型、五官和体型，只改变本次指定的服饰、发型、妆容或状态；年龄、体型等剧情变化按明确事实处理，不借换装重新选脸。
- 返修：先实际打开当前图，指出哪个视图、哪项特征出了问题；只修受影响范围，不重做已接受人物或其它角色。

只写人物心理、动机或冲突时使用编剧方法；只改表演或分镜时复用既有人物事实，不因出现角色姓名就启动外形设计。创作作者、工具和生成权限沿用当前任务，文本设计不自动授权生图、上传、视频试片或重试。

## 分开身份、造型与镜头状态

| 层 | 写什么 | 怎样保持一致 |
| --- | --- | --- |
| 固定身份 | 年龄感、脸部轮廓、五官比例、体型、基础肤色及已有稳定特征 | 跨服装、表情和光线仍能辨认；变化须有当前任务或剧情依据 |
| 当前造型／可见状态 | 发型发色、眉妆唇妆、服装结构与配色、鞋、饰品、胡须、伤情 | 同一 `lookId` 的各视图完全一致；明显变化按项目规则使用对应造型 |
| 镜头表现 | 眼神、表情、动作、受光、环境 | 随剧情设计，不把一次冷光、微笑或紧抿嘴当成固定脸型和肤色 |

发际线、天然眉形与基础唇形可属于身份；刘海、修眉、口红属于当前造型。疤痕先核实是稳定特征还是某集新增伤情。不要用镜头光色代替肤色，或用“总是微笑”锁住人物后续表演。

## 让人物在结构上有区别

从故事需要与现有角色出发，先把气质意图落实为可见外形，再用简短气质描述校准整体感觉。不是禁止“清冷、温和”等词，而是不让这些词成为唯一设计。

1. **先定整体轮廓与比例。** 描述脸的长宽关系、额头／颧部／下颌的相对宽窄、面颊丰瘦、下巴长短与形状，以及身体轮廓。脸型名称只是概括，要与具体描述相容。
2. **再选有区分度的五官组合。** 按需要写眉形、眼裂长短与眼距、眼睑、鼻梁鼻头鼻翼、唇形和下巴的关系。选能在目标画面尺度上看见的差异，不堆互相抵消的细节。
3. **让自然质感符合人物与画风。** 写实人物可保留适度皮肤纹理、肤色变化和自然不对称；卡通、水墨等按自身造型语言处理，不强加毛孔、衰老或瑕疵。
4. **识别特征按需使用。** 痣、雀斑、眉形缺口或疤可辅助辨认，不要求每个人都带一个，更不把单边耳饰当成不随造型变化的永久身份。已有外形足够清楚时不加额外标记。

同场或容易混淆的角色可用简短对照表比较“脸部轮廓、五官组合、体型、当前造型”；只覆盖本次相关人物。先确认去掉衣服颜色和光色差异后仍可区分，不以增加角色数量或重做全剧素材来补表。

例如，“面部短而宽、面颊丰盈、下巴短圆、眼裂较圆”和“面部偏长、颧部轮廓清楚、下巴较宽、眼裂狭长”提供了可比较的设计方向。这只是文字示例，不是已验证模型效果，也不分别绑定善恶、职业或性格。不要给所有男性统一添加高眉骨、宽肩和胡茬，或给所有女性统一套尖下巴、大眼睛和白皮。

**精确数字不等于精确控制。** 默认用相对位置和形状说明可见结果，如“人物自身右眼外眼角下方的小痣”；区分人物左右与画面左右。只有确有尺寸需求和可核验依据时才写毫米、角度或比例，不承诺模型准确执行。不让一个极小的点承担整个人物身份，也不要求背面或被遮挡的特征透过身体显示。

## 写成一张标准图的提示词

采用现有 [人物标准图](../../../director-knowledge-base/图片素材/人物标准图.md) 规范：**一个人物 × 一套造型或状态 × 一张图，包含全身正面、严格侧面、全身背面和清晰头像特写。** 不把文章里的四分之三侧全身替换进来挤掉大头像，不默认另做气氛定妆图或多角度头像组。

可按下面职责组织正文，简单任务可以合并段落；它不是必须填满的新表单：

| 内容 | 写作重点 |
| --- | --- |
| 人物与用途 | 规范全名、当前年龄阶段和造型、本图承担的身份与服装参考职责；已有参考只引用当前项目内的确切版本 |
| 固定外形 | 本次确定的轮廓、五官组合、体型及必要识别特征，避免仅写“绝美、标准、完美” |
| 当前造型 | 从头到脚的同一套服装与鞋、发型、饰品、妆容和伤情；补清后续会看见的侧面、背面结构 |
| 视图与姿态 | 正面与头像看清脸，侧面接近严格 90°，三个全身像头脚完整；中性自然站姿，手不遮脸、不遮必要服饰结构，视图分开不重叠 |
| 光线与画风 | 项目选定的画风、中性干净背景、便于比较结构的柔和照明；避免强戏剧光、过度磨皮或景深隐藏必要细节 |
| 一致性与排除项 | 各视图同一身份和当前造型；无文字、网格、编号、Logo、水印、无关环境或额外人物；具体补充当前已发现的冲突 |

标准图的多个视图是同一人物的展示，不写成同场多个角色。正面和头像的朝向要求不施加到侧面或背面；手脚在全身视图完整可见，不照搬半身肖像里的“双手不入画”。图片版式按清晰度与入口能力确定，不从文章继承固定 16:9，也不改变剧级视频画幅锁。

复用人物时沿用同一份外形事实与当前标准图，后续镜头简短点明全名、当前造型和参考职责即可；不规定统一字数，也不在每镜重新发明五官。纯文字、固定种子或重复短句均不作为已经锁定身份的证明。

## 在现有创作闭环中检查

- **生成前读正文：** 脸型名称与具体轮廓相容；唇色、发色、眉形、服装和左右位置没有重复冲突；固定外形与镜头表情分开；头像和全身视图的造型一致。方向未定的候选不能伪装成用户确认。
- **生成后看实际图：** 同时看大头像与全身视图的小脸，检查身份、严格侧面、身体比例和完整衣鞋；比较相邻角色的实际轮廓，不凭文字标签断言已经差异化。按 SOP 原尺寸检查，模糊、缺失或未查看的范围如实记录。
- **只有换装时：** 对照已确认人物图，核对眼鼻唇与轮廓没有随衣服一起变化；编辑前看原图，输入方式服从用户要求，不能为保脸偷偷增加图片参考。
- **只有进入视频时：** 依现有门槛复用或开展已授权的代表试片，实际看转头、近景与全身表现；不从一张肖像推断跨镜头、跨风格或连续视频一致性。不要默认同时输入气氛定妆图和标准图来加强身份。

未实现已确定的主要轮廓、换脸或视图造型冲突时，说明可见问题和受影响消费者；小痣的不可见微差、自然不对称或审美偏好不自动触发重跑。用户已接受具体用途后按根规则停止可选返修。

## 保存与交付

沿用 [AGENTS.md 素材 schema](../../../AGENTS.md#31-项目素材-schema创建前必读) 和正式索引，不另建脸型库目录或新素材类型。外形设定进入角色文档，生图正文用 `prompt.image`，正式人物图用 `image.character`；落盘前明确现有五字段，图片对应完整 `characterId + lookId` 和真实消费者，新版本保留旧文件。

生成入口只遵循 [SOP 生图工具默认路由](../../../PRODUCTION_SOP.md#image-generation-routing) 与当前用户指定，不从教程标题推断可调用模型。已授权生成时完成当前项目内落盘、正式绑定和 API／页面回读；只要求设计时交付设计和提示词即可。分别说明文字完成、媒体生成、实际查看、业务接入与人工接受，不因本技能被调用而提升素材状态。

## 来源与证据边界

本技能按用户要求吸收[《GPT Image 2.5 做 Seedance 2.5 角色脸型库：20 张提示词全公开，附 220 张完整版》](https://mp.weixin.qq.com/s/Tr6hAKdY-AJw1vK8c63n7Q)中的外形结构描述和身份分层思路，并适配本项目标准。2026-09-26 从用户提供的本地 HTML 读到 20 套提示词，抽看第 01、06、07、15 张配图；未取得 220 套完整版，也未验证跨镜头视频。

文章第 15 套唇色有深红／浅褐冲突，第 19 套有砖红／淡褐冲突；第 07 张配图的下巴仍明显收窄，不能凭“方脸”标签认定已实现目标轮廓。这些观察用于提示词与成图核对，不证明某个模型普遍失败。文章的毫米级身份控制、跨风格锁脸、模型参数及平台相似度阈值等未获本次核验，不作为能力保证或生产门槛；不复制其整套脸型模板作为独家人物资产。
