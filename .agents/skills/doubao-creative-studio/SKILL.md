# 豆包创作工作室

## 职责边界

- 豆包是创作文本的唯一作者：剧本、剧情梗概、分镜创意、素材生成提示词、视频生成提示词和创意返修都由豆包完成。
- 当前 Agent 是执行者：选择事实源、组装任务包、调用 CLI、保存原文、检查硬约束、执行已确认内容、实际检查输出，并把观察到的问题作为事实反馈给豆包。
- 当前 Agent 不润色、续写或静默修补豆包的创意文本。结构或事实不合格时，新建返修任务交还豆包。
- 用户亲自给出的创意指令可以原样进入 `userCreativeDirectives`；不要把 Agent 自己的审美偏好伪装成用户要求。

## 固定调用路径

只通过本 Skill 的 `scripts/run-doubao-creative.mjs` 启动已配置的 `claude` CLI。脚本通过 stdin 传入完整任务，关闭 Claude Code 工具，仅读取用户级 Claude 设置，并默认不保存隐藏会话。

不要读取、复制或打印 Claude 设置中的 token，也不要绕过 CLI 直接请求 `/api/plan`。不要在 CLI 失败时静默切换豆包网页、Computer Use、其它模型或普通 API。

构造任务前读取 [references/job-schema.md](references/job-schema.md)。调用形式：

```bash
node <skill-directory>/scripts/run-doubao-creative.mjs \
  --job <absolute-job-json> \
  --out <new-versioned-run-directory>
```

先只校验任务包、不调用模型：

```bash
node <skill-directory>/scripts/run-doubao-creative.mjs \
  --job <absolute-job-json> \
  --check
```

查看当前内置模板：

```bash
node <skill-directory>/scripts/run-doubao-creative.mjs --list-templates
```

只读校验已有豆包输出是否符合任务模板，不再次调用模型：

```bash
node <skill-directory>/scripts/run-doubao-creative.mjs \
  --job <absolute-job-json> \
  --validate-output <absolute-creative-output>
```

## Claude CLI 单次输出上限

- 当前本机链路中，`claude -p --output-format json` 可能在 stdout 达到 **4000 个 Unicode 字符**时截断，仍以退出码 0 结束，并留下未闭合 JSON。该限制发生在 Claude CLI 或其上游兼容网关，不是 runner 的 16 MiB 进程输出保护。
- 在完成受控诊断并证明上限已变化前，把它视为有效硬约束：每个任务要求豆包最终创作正文不超过 **2500 个 Unicode 字符**，让外层 JSON、模型用量和运行元数据保留安全空间。
- 2500 是当前豆包 CLI 单次返回的传输安全线，不是视频生成模型的提示词上限。不要套用额外的固定字符门槛，也不要为接近上限而扩写；目标入口若有真实限制，执行前读取当前入口规则并按实测长度判断。
- 预计超过上限时，按创作责任拆任务，例如“开场剧本返修”“补图决策”“U01—U02 分镜提示词”；不要要求一个调用同时返回整集剧本、全部补图清单和全部提示词。一个任务最多承载两条短提示词，复杂模板任务一次只做一条。
- `--check` 只能校验输入包，不能预知模型输出长度。把正文字符上限同时写进 `deliverables` 和 `hardConstraints`。
- 若 `raw-stdout.txt` 恰好为 4000 个 Unicode 字符、以字符串中途结束或报 `Unterminated string`，标记为上游输出截断。保留证据，禁止从残稿拼接创作结果，也不要原样重试；缩小范围后使用新的 job ID 和输出目录。

## 模板能力

模板只固定交付结构、字段顺序和可客观检查的格式，不替豆包写创意内容。需要模板时先读取 [references/template-catalog.md](references/template-catalog.md)，在任务包中填写 `template.id` 与模板要求的变量。脚本会加载本项目 Skill 内的模板、填入事实型变量、交给豆包完成正文，并对返回结构做确定性校验。

- 当前只使用 `video-shot-prompt-v1`：它适用于任意目标视频模型的分镜或生成提示词，固定采用 `风格 → 空间与轴线 → 时间轴 → 声音 → 参考`，`禁止` 仅在确有高价值风险时保留。不要按模型拆模板；以后只有用户确认出现稳定差异时才新增模板。
- 模板状态不是豆包自评。首次创作默认使用 `DRAFT`；只有执行者已经完成核心剧情可见性、时间轴、素材职责和实际输入核对时，任务包才可传入 `READY`。
- 所有 `video-shot-prompt-v1` 任务都必须提供 `referencePlan`。执行者先列明镜头实际场景、出镜人物和逐项生成输入；runner 会拒绝缺场景、缺人物身份输入、引用 INTERNAL/REJECTED/SUPERSEDED、或把局部辅助输入排在基础母版之前的任务包。`DRAFT` 可声明尚未验收的 DRAFT 素材，`READY` 只接受 `GEN_INPUT`/`ACCEPTED`。
- `〖参考〗` 采用用户认可的 EP05 职责句式：场景图锁空间/材质/光色，人物身份图锁脸部身份，状态/道具只锁对应变化，空间板/连续帧/关键帧只作局部辅助。头像和同一人物三视图可同时存在：三视图必须是项目批准的 `GEN_INPUT / ACCEPTED`，只补充体型、轮廓与同一造型前侧背结构，并明确忽略三联排版和中性站姿，禁止复制重复人物、拼板、文字或影棚背景；仍为 `INTERNAL` 的母版不得写进实际生成输入。
- 新建视频任务时用 `referencePlan.turnaroundDispositions` 逐个声明可见具名人物的三视图是 `CONNECTED`、`NOT_APPLICABLE`、`BUDGET_EXCLUDED` 还是 `CONFLICT`；不能因为 `assets` 里没有三视图就默认“不需要”。旧任务缺少该字段仅作历史兼容。
- 模板中的集数、Task ID、标题、版本、总时长和画幅来自任务事实；不得把示例中的 EP05、30 秒、16:9、人物、动作或 `Mixed` 编号带入其它任务。
- 没有合适模板时不强套。先使用普通 Markdown/JSON 输出，等用户确认一种稳定结构后再把它新增为内置模板。

## 工作流

1. **确定本轮边界**：写清交付物、事实源、用户原始创意指令、硬约束、是否只是试验，以及下游是否允许生成媒体或产生费用。创作调用本身不代表用户授权生图、视频生成、发布或其它外部写入。
2. **选择最小事实包**：只声明本任务真实需要的文本文件或内联事实；脚本不会扫描仓库。已确认剧本、角色设定和接受过的素材状态优先于旧方案或推测。视频提示词还要把镜头实际场景、出镜人物和逐项素材写入 `referencePlan`，不能只列“打算引用的几张图”。
3. **选择调用粒度**：Claude Code 有显著固定上下文开销，同时受上述单次输出上限约束。默认一次提交一个完整场景或一批不超过 2500 字符的同类创作文本；整集内容预计超限时按创作责任拆批，不按文件数量机械拆批。该拆批规则不要求单条视频提示词接近 2500 字符。
4. **选择输出模板**：用户指定格式或存在已确认模板时使用 `template`；模板不匹配当前交付物时不强套。模板状态、Task ID、版本、时长和画幅只填事实。
5. **指定模型**：任务包必须写 `expectedModel`。脚本把它通过 `--model` 显式传给 Claude Code；当前 Skill 只接受 `doubao-` 开头的模型。Claude Code 返回的模型元数据只作记录，缺失或与请求值不同均不阻断结果。
6. **保留证据**：每次运行使用新的输出目录。脚本保存原始任务、渲染后的模板、发给豆包的完整任务文本、Claude 原始响应、豆包创作原文和运行记录；不得覆盖旧版本。
7. **只做硬校验**：检查缺字段、剧情事实冲突、人物或素材遗漏、时长/数量/文件 ID、参考素材职责、模型限制、模板结构和用户明确禁区。对带 `referencePlan` 的视频提示词，`--check` 必须先通过素材覆盖，`--validate-output` 再通过引用关联与顺序；不得以“更好看”为由自行改写。
8. **返修仍由豆包完成**：把实际观察写入 `repairFeedback`，包含失败现象、证据和必须修正的结果；附上上一版输出作为明确来源，再运行到新的版本目录。不要盲目重试同一任务。
9. **交付与执行分层**：先让用户确认剧本或创作包。若用户还要求生产，再进入当前项目适用的素材、视频、剪辑和质检流程；收费生成仍需单独明确授权，所有输出都必须实际查看后才能接受。

## 黄金样本闸门

用户已经认可的豆包网页/App 对话或成品是黄金样本。首次把一种创作任务迁移到 CLI、切换模型或准备批量生产时：

- 把原输入和认可输出放进 `goldenSamples`，在同一事实包上先做一轮 CLI 对照；
- 比较剧情因果、动作可见性、语言风格、约束遵守和可直接执行程度；
- 未达到用户认可档位时只标记为试验，不批量铺开，也不让当前 Agent 代写补齐；
- 没有黄金样本时允许单次探索，但明确标记 `GOLDEN_SAMPLE_PENDING`。

## 成功与停止条件

一次运行只有同时满足以下条件才算“豆包创作已返回”：CLI 成功退出、响应 `is_error=false`、结果可按指定格式读取、模板与 `referencePlan` 硬校验通过、运行证据已保存。任务指定的 `expectedModel` 与 Claude Code 回报的模型元数据都会保存在证据中，但模型元数据不作为成功闸门。它仍不代表创作内容被用户接受，也不代表下游生成完成。

遇到 CLI 鉴权、模型不可用、超时、输出格式错误、4000 字符上游截断或硬约束失败时停止在对应层，保留证据并报告。未经用户新增授权，不修改 Claude 全局配置、不切换模型、不触发媒体生成。
