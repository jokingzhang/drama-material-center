# 连接与只读检查

用于用户要求连接 Blender、接着当前工程修改、跨会话继续或连接超时的情况。新建独立工程直接使用后台生成器即可，不必先设置文件桥。

## 先确认控制的是哪个实例

1. 发现当前可用 Blender 工具；读取其真实参数。先调用只读场景查询，取得 Blender 版本、PID（能取得时）、当前文件、活动场景和时间线。只有成功回读才报告已连接。
2. 用户指定原窗口时，核对该实例的文件名、场景和未保存状态。新开的可交互实例与后台进程分别报告，不能冒充原窗口。无法接管原窗口时先定位实际工具/连接问题，独立新工程仍可在已授权范围内推进。
3. 有启动记录或 `connected.json` 时，先看它怎样生成。启动时写一次的标记只能定位旧实例；记录很新不证明请求可执行，记录很旧也不证明实例已经离线。实际只读响应才是连接证据。
4. 读取场景概览后，只展开本次相关的对象、约束与动画。留意同名 `.001` 对象、错误场景、隐藏集合、相机标记和渲染分辨率百分比。大场景不要先倾倒全部 mesh 数据。

## 检查磁盘上的工程

用已安装的 Blender 读取已保存文件。下面的脚本不移动帧、不渲染、不保存工程；`--output` 只允许创建新 JSON 文件。

```sh
/Applications/Blender.app/Contents/MacOS/Blender \
  --background --disable-autoexec /absolute/path/shot-v01.blend \
  --python-exit-code 1 \
  --python .agents/skills/blender/scripts/inspect_scene.py -- \
  --object 'CAM S01' --output /absolute/path/new-inspection.json
```

省略 `--object` 得到各场景的对象数量、类型、集合、相机、切点、当前帧、帧率、尺寸、单位和外链库；可重复 `--object` 展开指定对象的父级、变换和约束，`--scene` 选择要检查的场景。CLI 参数中的实例模式、PID、脏状态和文件路径会一起返回。

在已验证的交互 MCP 内，可通过 `runpy.run_path` 加载同一脚本并调用 `inspect_scene()`，将返回字典交给工具输出；不要重新执行后台启动命令。此时 `mode` 才是 `interactive_instance`。先查看工具支持的只读接口，已有接口够用时无需执行通用代码。

后台打开文件时禁止自动脚本执行，用于静态检查未知工程。依赖 Python driver 的场景不会因此得到完整动画验证；需在确认可信、符合当前授权后按其实际依赖检查，不能把禁用后缺失的运动误判为原动画错误。

## 超时与已有文件桥

先读桥实现、实际目录、未完成请求和回执；回执必须匹配本次请求 ID。超时可能表示渲染仍在执行，不能直接重复建模、另启窗口或覆盖请求。消费者取走请求文件不等于执行已经结束，尤其要等匹配回执或核对实际副作用。

文件桥若用于本次任务，应只在本机私有目录内运行，一个消费者、一个写入客户端、一个未完成请求；新实例使用独立空目录。恢复停用桥之前先处理遗留命令，避免启动后突然执行旧修改。不能依据目录名“最新”就认为它是活动连接。

本 Skill 没有安装附件里的文件桥，也不要求使用该实现。若确需新建桥，先检查本地实现的执行范围、请求认领、完成回执及并发行为，再在独立实例验证只读请求。不要直接运行下载包里的启动器或把其中路径、进程状态当作本机事实。Skill 优化请求本身不要求安装常驻服务。

## 编辑与恢复

修改前保存当前任务的新版本；交互批量操作可增加撤销点，撤销不能代替备份。设置 mode、selection、active object 后再用依赖上下文的 `bpy.ops`；后台不得假定 `bpy.context.window` 存在。新物体创建后立即保存对象引用，不依赖自动编号。

连接报错、工具权限、场景错误和设计质量分别诊断。某模型在已连接的工程中续作成功，只证明该次运行；不能推断它独立建连必然成功或失败。保持实例、工具、工程与请求一致，才有可比较的模型观察。
