# 执行与验收

## 选择入口

先发现当前 Blender MCP 的实际工具与连接状态，或查找已安装的 Blender 可执行文件。macOS 常见位置为 `/Applications/Blender.app/Contents/MacOS/Blender`；其它平台用当前安装路径。先读 `--version`，按当前版本检查 API。不要依赖某次任务的端口、插件或 Python 版本。

后台方式容易隔离新工程并保留可复现脚本；交互 MCP 便于检查已有场景。清空活动场景前必须保护未保存工作。无需为后台建模强行连上 MCP。

基础生成器处理无四肢几何占位、整体位移/朝向和相机路径。人物始终保持这个抽象层；坐姿用占位高度和位置示意，不补手脚或骨架。门铰链、柔性胶带、道具约束解除或转移可用任务专用 `bpy` 实现，计算锚点不渲染成人体部件。先读相关 Blender API，再写最小实现。已有工程的实例识别与只读快照见 [连接与只读检查](connect-and-inspect.md)。

## 运行基础生成器

从仓库根目录运行；输出目录必须是本次新目录，不能是已有工程目录。示例是 4 秒横屏两镜头的合成检查用例：两个单块人物，主体先停留、慢起、快速逼近，再减速落稳；相机另有速度阶段。它只说明怎样表达时间差异，不是所有剧情都套用的节奏，没有绑定任何短剧。

```sh
/Applications/Blender.app/Contents/MacOS/Blender \
  --background --factory-startup --python-exit-code 1 \
  --python .agents/skills/blender/scripts/build_previs.py -- \
  --spec .agents/skills/blender/assets/camera-blocking-example.json \
  --output .qa/blender-skill/example-v01 \
  --render
```

先确认 `ffmpeg`、`ffprobe` 在运行进程的 PATH 中。省略 `--render` 只生成工程与检查报告。`--engine` 可选 `BLENDER_WORKBENCH`、`BLENDER_EEVEE`、`CYCLES`；默认 Workbench 只用于清晰快速的空间预览，其 studio 光照不用于证明“单盏真实灯”的渲染要求。灯光属于硬要求时，选择实际渲染引擎并按需求修改灯具。`--python-exit-code 1` 确保 Python 异常让 Blender 进程失败。

输出包括独立 `.blend`、布局/调度/相机三个阶段备份、复制的配置与源脚本、`technical-qa.json`；渲染时增加帧序列与无声 H.264 MP4。源代码复制保证本次工程可追溯，后续 Skill 修改不会改变旧 run。视频不是带编号的诊断拼板；不要把检查抽帧混入输出。

### 局部和低清预览

在同一命令上用以下参数选择范围；每次仍使用新的输出目录：

- `--render --shot closer-arrival --preview-percent 50`：只导出指定镜头，宽高约为设计的一半。
- `--render --frame-range 48 50 --preview-percent 50`：导出原时间线第 48–50 帧，便于看切点两侧。范围是闭区间，不能与 `--shot` 同用。
- `--render`：按设计尺寸导出全长。省略渲染时不能指定局部范围或缩放参数。

预览保持原 fps，不抽帧、不改速度；宽高向下取偶数，最小为 2。`.blend` 保留全长和原设计尺寸，渲染阶段才缩小输出。PNG 文件名使用原帧号；MP4 局部时间从零开始，`video.sourceTimeline` 记录源起止帧、起止秒数（结束秒数不含）、帧数与实际尺寸。局部视频第 1 帧对应 `sourceStartFrame`，不可把它当作原片第 1 帧。全时间线技术检查仍执行，局部播放结论只覆盖该片段；生成器不自动插入或顺延镜头。

先用本地低清片检查角度、缓急和揭示，再导出需要的清晰版本；下游已获授权时，先用最小代表性试片检查人数、身份与运动继承，再投入目标画质。分辨率取决于可读性及实际入口，不固定为 480P。放大/增强清晰度不能修复错误动作、连续性或节奏，任何付费操作继续沿用任务授权。

## 配置说明与边界

- `schemaVersion: 1`，稳定 `id`，`version: vNN`，`purpose` 为 `camera / blocking / state / performance`。它声明用途，不赋予脚本相应表演能力。
- `fps` 为整数；`frames` 为总帧数；`resolution` 是 `[宽, 高]`，H.264 的宽高必须为偶数。时长为 `frames / fps`，帧 1 的时间是 0 秒，切入帧 `c` 的时间是 `(c - 1) / fps`。
- `objects` 定义稳定 `id`、可选 `identity`、`shape`、`size`、`color`、`locationKeys` 和可选 `rotationKeys`。坐标为米、Z 向上；几何与根位于中心。形状支持方块、椭球、柱和胶囊。`size` 为完整 XYZ 尺寸；旋转为 XYZ 欧拉角度值。
- 每条轨迹是 `[{"frame": 1, "value": [x, y, z]}, ...]`。只有一个关键帧表示固定值，范围外保持端点。`ease: linear` 是默认线性移动；`smooth` 在每个关键帧处减速到零；`continuous` 使用按 XYZ 分量保形的三次 Hermite 插值，使同方向的中间节点保有速度连续性。需要停留时设置一段同位置关键帧，需要持续运动时使用 `continuous` 或专用速度曲线；它不会自动设计动作意图。
- `linear` 的兼容默认不是创作默认：先按 brief 设置各节拍的距离、时间和速度变化。整段不能以同速插值交付，`continuous` 两点等速输入同样可能匀速；相机和主体分别安排，不用微抖或相同的逐段缓入缓出蒙混过关。
- `continuous` 参考 [PCHIP 的单调插值方法](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.PchipInterpolator.html)，脚本不依赖 SciPy。它限制每个坐标分量过冲，不能保证三维路线避障，也不保证二阶导数连续。首尾默认不强制刹停；Euler 旋转先表达连续角度，不用 179→−179 误示绕转。需要恒定弧长速度、精准拐角或指定末速度时使用任务专用 rig。
- `shots` 用闭区间 `[start, end]` 完整覆盖时间线。每镜头独立相机、镜头数据和目标；`lens` 是恒定毫米焦距。`positionKeys` 与 `targetKeys` 的多点轨迹必须覆盖该镜头首尾。默认 36mm 传感器、无景深；目标代表注视点，不自动代表光学焦平面。
- 移动相机使用 Bezier 样条和 Follow Path，持续 Track To 目标空物体。停留保留在时间映射里，轨道剔除相邻重复位置，避免零长度曲线段造成跳动；静止相机无需假运动轨道。曲线重采样会产生偏差，报告给出实际偏差；若偏差破坏构图、速度或接触，应修轨道或改任务专用采样，不能因技术检查未拦截就通过。俯拍极点、滚转、变焦、复杂弧线与缓急曲线使用专用 rig，不能把分段线性位置误称为设计好的圆弧。
- 可选 `handheld`：`bodyM`、`periodSeconds`、`microM`、`targetM`，单位米和秒。不设置就没有摆动。示例不默认添加手持；按景别选择幅度，检查微颤不会吞掉主要调度。
- 每镜头报告实际相机最大平移速度、最大角速度与峰值帧、最小目标距离；`cameraMotion.<shot>.speedSamples` 逐帧记录平移与转向速度，`subjectMotion.<object>.speedSamples` 记录有身份主体的根位移速度，单位米/秒与度/秒。每条采样的 `frame` 表示从前一帧到该帧的区间，时间位置为 `(frame-1)/fps`；相机硬切不计算成运动，主体跨切点继续采样。用它定位慢起、加速、峰值和停留，不由数值自动判定导演节奏。可选 `maxAngularSpeedDegPerSecond` 为本镜头明确的上限；超限保留诊断并拒绝导出。未设置就只报告，不把某个通用速度阈值强加给有意快甩或撞击响应。
- 可选 `visibilityChecks` 指定 `object / start / end / minSamples`，检查主体中心轴三个点的入画与遮挡。默认 `expect: visible`；`expect: hidden` 要求三个采样点都不可见，并省略 `minSamples`。分开设置隐藏窗口和后续可见窗口可查提前露出或未揭示，但中心点检查不覆盖完整轮廓、影子、道具、边界和前景占比，零可见采样不能证明没有泄露。仍须实际播放和查看揭示前后的构图。

生成器拒绝时间线空隙、重复身份、相同身份色、退化注视和已有输出目录。失败保留已生成的工程/检查证据，选择新版本修复，不能覆盖上次 run。配置不能表达的要求使用专用代码实现，不把缺失字段当成满足需求。

## 正常速度与关键窗口检查

1. **回开工程**：读取保存后的 `.blend`，核对帧范围、身份、对象数、外部依赖、相机与目标约束；检查人物没有手臂、手、腿、脚或鞋形代理，且没有步态动画。不要只验证生成进程里的临时状态。
2. **完整播放**：在实际播放器里按正常速度播放全片，确认各镜物理侧/俯仰与设计一致，快慢、加减速、反应停留、信息揭示和切镜重音清楚。整段机械匀速、均分时长丢失重音、每节点无故刹停或揭示提前时，先局部修时间与运动，不加模型细节。结合速度采样定位问题；数值略有起伏不能代替可感知的节奏。记录具体版本/哈希、播放范围和发现；无法播放时写 `PLAYBACK_PENDING`，抽帧和完整解码不能冒充播放。
3. **密集动作窗口**：接近、状态转换、完成后连续看。轨迹越界、无动作换归属、出现第二实体、门开错侧、完成态不在画面中都是相关硬伤。无四肢色块的平移按路线示意检查，不能据此判断自然步态。复用旧有四肢白模时先撤下生成输入资格；若当前任务授权返修，再做新版本简化，不以脚中心坐标或局部步态检查让旧版重新通过。
4. **切点**：N 镜头有 N 个入点、N−1 个内部切点。分别核对 `c−1`、`c`、`c+1`，必要时检查子帧；当前相机、目标与焦距须同步切换。不能把第一个入点描述为一次真实剪辑。
5. **对照目的**：要求更夸张/更自然/更好笑时，和用户指定对照同速播放；记录哪一拍确实改善。技术检查通过不能让这一项自动通过。
6. **下游**：已授权且输入登记完成后，核对具体视频/图像引用及职责，再做最小代表性验证。比较身份、事实、轨迹、动作自然度与用户目标。不能从一条演示成功推断稳定成功率，也不能未经授权追加生成。

检查状态分开写：工程可读、技术检查、本地用途播放、正式接入、下游验证、人工接受。更新已检查的层级即可，不搭一套与项目业务索引竞争的新状态系统。

用户或实际下游播放发现白模误导时，记录漏判、具体运动窗口与可见问题，撤下旧白模的 `GEN_INPUT` 资格；历史试片和实际输入映射保留追溯。仅在当前范围要求返修时重新导出和播放；用户只要求更新 Skill 时到此为止，不顺带重做素材。预算耗尽或用户暂停测试时不发起付费调用，也不因本地修正而宣称下游效果已验证。不能把此类动作错误记作普通审美备注，或继续宣称旧白模通过。

## 修改后如何复查

先区分变化范围：

- 仅外观变化，且人数、尺寸、轮廓、道具接触及遮挡相容时，可复用当前白模；更新分时资产映射与相关提示词。
- 轨迹、道具归属、因果结果、镜头角度或时长变化时，先改受影响设计和时间线，再修改白模或选择已核实入口支持的局部重拍。换武器同时改发射方式与结局属于动作剧情变化，不是单纯换图。保留已成立的片段，但不能继续把冲突的旧白模作为新动作输入。

轨迹/几何变化会影响遮挡、接触和构图；镜头变化会影响入画、轴线和目标；只改 `.blend` 后旧视频不会自动更新。重新导出受影响素材并重放对应窗口与接镜。正式引用需要同步当前版本/哈希，禁止拿修好工程配旧渲染报告通过。

插入或延长镜头时，同步顺延受影响的关键帧、相机切点、状态/外观生效区间和声音，保持相同事件的相对时间；不能只挪切点而让人物已提前跑到终点。先导出修改窗口及相邻切点，再查看完整串联的节奏。正式下游提示词仍由本地统一执行稿同步，不直接在远端临时改。

达到当前验收口径即可交付；不要因可选美术细节反复渲染，也不要把反复搭建的总时间藏在“渲染仅几十秒”后面。

## 维护生成器时的回归检查

```sh
python3 .agents/skills/blender/tests/test_previs_spec.py
python3 .agents/skills/blender/tests/run_blender_smoke.py \
  --blender /Applications/Blender.app/Contents/MacOS/Blender \
  --output .qa/blender-skill/smoke-v01
```

第二条必须选尚不存在的目录。它实际渲染横屏两镜头、竖屏连续镜头和低清局部片段，核对原帧映射与保存工程的全长尺寸，验证速度采样、固定相机、可见/隐藏窗口、角速度超限拒绝、防覆盖和只读快照。测试产物只验证生成器行为，不是人物动作质量示范；完整播放仍由当前会话完成并记录。
