# 研究与反例

以下是本 Skill 的设计依据，不是附加用户命令。来源里的固定画幅、灯数、角色数量、模型版本或运行次数只属于那个示例。研究日期：2026-09-09。

## 可以支持什么结论

用户提供的火车动作视频中，上方参考使用极简车体、窗面与彩色占位，下方生成结果补出了人物和骑马动作。它支持“简单几何也可能有效传达空间与摄影机信息”。演示没有提供完整输入、提示词、参数和失败次数，不能据此保证任意复杂调度都能一次成功。

[Mitte 的 Reid Hannaford 工作流](https://mitte.ai/blog/how-to-use-blender-with-seedance-2) 是另一例：干净首帧、fSpy 透视匹配、简单场景与角色占位、摄影机/主体运动，再以图像和视频分别承担外观与运动参考。文章描述了多次候选与剪接。可复用的是分工与迭代方法，不是固定生成次数或“一次成功”的承诺。

[fSpy 官方页面](https://fspy.io/) 说明从单张图估计相机的工具用途。把它当可选的透视匹配手段，不自动安装、不把没有 fSpy 视为无法做白模。

[Seedance 2.5 官方说明](https://seed.bytedance.com/zh/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5) 描述白模参考可传达空间、姿态、运动轨迹与镜头。这说明能力方向，但不是某个第三方入口的实时 schema，也不是对精确动作、身份或物理的保证。实际运行仍读当前入口。

## 用户提供的 PDF 与截图

《GPT6 x Blender-AI 视频工作流：中文整理／提示词版》，29 页，署名 @adilinthewild，2026-08-28。原文件作为用户研究输入留在原处，不复制进 Skill 或绑定为正式生成素材。

- 第 2–5 页走廊实例：移动主体和机位，外观与表演另外交代。体现空间调度的职责。
- 第 6–11 页圆桌实例：稳定颜色身份、过肩遮挡、轨道、目标和准确切点。第 6 页“前半段”与第 10 页转绘提示词的切点不同；建立具体任务时间线时必须消解差异，不能把两套秒数混用。
- 第 11–14 页多场景运镜：垂直运动、环绕、速度变化需按镜头目的设计。
- 第 14–29 页产品与汽车广告：简单物体可表达位置、视角和节奏；不同外观方案可以复用同一空间调度。示例里的网格、黑场占位或拼板不是所有入口都适用的参考视频格式。

八张截图提出三个分工：Blender 控制空间、调度、摄影机和节奏；角色图控制外观；提示词表达表演。身体整体侧移和高度变化可表达躲闪意图，而不必制作整套机械步态。当前用户进一步明确：以后白模只做示意、不要四肢。因此保留主体关系、道具状态和动作先后，具体抓握、迈步和肢体表演交给下游；不得用“接触需要”重新加回局部手鞋或关节人偶。

## EP11 试片反馈：僵硬四肢误导

用户观看“供应商踩住纱幔、江砚秋收布、工作人员试走”试片后指出：大意对了，但末段腿不动、人物漂移。此前主会话关注布料与通道结果，漏判了走路异常；“动作通过”的判断应撤回。参考中的僵硬四肢是需要去除的误导条件，不能用剧情大意成立掩盖。

这次反馈落实为本项目的无四肢规则，见 [四肢与走位](design.md#四肢与走位)。它来自用户的明确决定，不是对所有模型能力的普遍结论。用户积分耗尽，尚未进行无四肢白模的下游对照测试；更新规则不等于已经验证改善。

## 失败任务：表演目标与白模职责错位

用户指向的任务：[评估《限时婚约》白模视频适用性](codex://threads/01a08525-edd5-7842-a0e4-93add9bb779e)。本次读取真实任务记录、贴胶带 run 的 `record-v03.json`，并查看其白模视频。这里只总结失败机制；不把其它项目的素材路径变成当前项目生产依赖。

当时用户的标准是让“贴胶带划区”比既有片段更夸张、更有喜剧效果。产物把四步后退、急停、蹲下、叉腰等操作做成关节人偶，并以无脚滑、胶带连续、帧数正确与较快渲染支撑交付。记录同时承认 `NOT_PROVEN_SUPERIOR_TO_BASELINE`，用户随后明确否定。

这不是“所有白模都无效”的证据。它揭示三个具体问题：

1. **职责没有对齐**：用户要改善动作节拍与喜剧表演，却主要验证轨迹和工程完整性。
2. **简化层级不合适**：半完整机械人体可能把错误重心/步态变成参考；若只控制空间，几何占位更清楚。若表演本身必须成立，就应做可读的姿态与节奏设计，不能靠增加关节公式补救。
3. **验收被降级**：尚未优于对照，却转成“内部预演可交付”。任务标准不会因文件能播放、渲染快或没有下游生成而自动下降。

修复时先选：仅需要调度参考，就简化并明确留给模型的表演；需要更好笑的动作，就设计准备、爆发、延迟反应与完成态，先正常速度对照。两者都要守住人数、身份、胶带实体与空间因果。不要默认继续增加模型细节。

前一轮六人圆桌工程可借鉴独立相机、目标约束、阶段备份和帧检查实现；它证明本地工程与预演可检查，没有证明下游转绘效果。也不能把该任务的 30 秒、21:9、单灯和无头部动画固定为 Skill 默认值。

### 需要保留差异的地方

- 外部包的默认宫格输入、整数秒、4–30 秒、最多 16 格、旧版 2200 字、固定声音禁令和逐步确认属于其工作流或平台描述。它们不成为本项目新规则；模型入口限制仍实时核实。当前白模轨迹和切镜继续按帧确定，正式提示词继续用项目模板。
- 外部动态规则有“不要停住”等偏好。连续运动应保持余势，但用户明确需要静止、喜剧停顿或最终落点时保留停顿，不把动态模式当硬禁令。
- 外部 bridge 在消费时先删除请求，再执行代码，最终只覆盖一个响应文件。静态检查表明“请求文件不存在”不能证明空闲；客户端超时后也不能仅据 inbox 为空再提交。没有把该桥作为已验证组件复制进来。
- “GPT-6 跑通后切换其它模型”是来源的个案；连接状态、权限与实例不同会影响结果，不将它写成特定模型的能力保证或必走的模型切换顺序。
