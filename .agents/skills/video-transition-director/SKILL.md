# AI 视频转场导演

把转场当作两个镜头共同完成的一次叙事动作，而不是夹在中间的特效。目标是让观众的注意力、动作、空间、情绪或声音有可追踪的去向；“丝滑”首先指观众能自然跨过接点，其次才是像素连续。

在 `drama-material-center` 中由 [ai-director](../ai-director/SKILL.md) 按需调用，也可以独立使用。遵守仓库 `AGENTS.md`、`PRODUCTION_SOP.md`、当前项目事实、版本和验收边界。设计文字不授权上传、生成、付费重试或远端写入。

## 按需读取

- 需要选择转场类型或比较替代方案时，读 [转场类型与选择矩阵](references/transition-catalog.md)。
- 准备生产、审查已有视频或返修接点时，读 [接镜 QA 与返修](references/qa-and-repair.md)。
- 用户需要独立转场表或批量接点设计时，复用 [转场接点模板](assets/transition-junction-template.md)；普通任务可直接把必要字段写进现有分镜，不强制新建文档。

## 核心判断

1. **先问为什么要转。** 明确这是同一动作延续、信息揭示、时间跳跃、空间切换、情绪联想、因果对照，还是刻意冲击。没有关系依据时，硬切通常比炫技更自然。
2. **先设计接点，再挑效果。** 同时查看 A 镜有效尾段和 B 镜有效开段，不能只为其中一边写“顺滑转场”。
3. **采用最小有效路线。** 优先顺序通常是有动机硬切/声音桥 → 动作、视线、遮挡、图形或运镜匹配 → 剪辑软件补帧或局部变换 → 独立生成桥段 → 首尾帧或视频编辑模型。更高一层只在下层无法表达当前关系时使用。
4. **只保一个主铰链。** 每个接点选一个主要连接机制，例如动作方向、圆形轮廓、前景全遮挡、同一声音或一次光线扫过；可有一个辅助机制，但不同时堆形变、甩镜、闪白、粒子和变焦。
5. **连续不等于不变化。** 身份、造型、人物数量、道具归属、场景几何等受保护事实必须稳定；时间、地点、季节、材质或画风只有在剧情要求时才变化。把二者分开写。
6. **声音参与接镜。** 画面切点、对白起止、环境声底、动作声和音乐拍点共同决定观感。能用 J/L 切或环境声桥解决的，不必生成复杂视觉过渡。

## 工作流程

### 1. 恢复两端真实状态

读取当前剧本、分镜、实际选片、人物造型、场景、道具和声音。已有媒体时正常速度播放 A→B，确认真正可用的出点和入点；计划尾帧不能替代实际尾段。

为接点写出：

- A 镜最后一个完整可见状态与未释放的动作/声音；
- B 镜第一个必须读懂的状态与动作/声音；
- 必须保持的事实；
- 允许或必须改变的事实；
- 观众注意力在切点前后落在哪里。

两端本来就矛盾时，先修最早出错的镜头或剪辑点，不用转场特效掩盖错人、错空间、错道具或动作跳变。

### 2. 选择叙事关系与主铰链

| 接点关系 | 优先主铰链 |
| --- | --- |
| 同一动作、同一空间或并行动作 | 动作顺接、运动方向/速度延续、遮挡切、声音同步点 |
| 人物观察到新信息 | 视线匹配、反打、焦点转移、声音先行 |
| 不同时空但有语义联系 | 图形/构图/色彩匹配、动作押韵、道具或声音桥 |
| 明确时间流逝 | 有依据的叠化、环境声与光色渐变、延时或状态蒙太奇 |
| 明确空间穿越或梦境 | 入口穿透、尺度钻入/拉出、场景融合；保持一个稳定视觉锚点 |
| 身份、材质、风格或世界规则改变 | 单轴形变、风格渐变、粒子/流体重组；只改变剧情要求的层 |
| 故意制造冲击或失序 | 硬切、闪白/闪黑、故障或甩镜；让形式与主观体验有因果 |

完整类型、适用条件和避用情况见 [转场类型与选择矩阵](references/transition-catalog.md)。

### 3. 写成 `A 出口 → 铰链 → B 入口`

- **A 出口：** 说明主体、画面位置、动作向量、相机运动、焦点、亮度/色彩和声音如何进入接点。
- **铰链：** 说明哪一刻承担隐藏切点或完成变化，以及观众当时看/听什么。遮挡必须真的覆盖必要区域；甩镜必须有方向与速度；形变必须有一对一来源和去向。
- **B 入口：** 继承主铰链的方向、节奏或声音，再落到新场景第一个可读状态。不要在切后立刻反向运动、重置姿势或无因改变道具。

自然转场不要求两侧所有属性一致。通常只需把观众最关注的一到两个维度对齐，其余差异服务叙事。

### 4. 明确执行边界

把方案标为以下一种，不混写：

- `EDIT_ONLY`：硬切、J/L 切、叠化、调色、遮挡点或现有素材内的变速/重定时即可完成。
- `AI_ASSISTED_EDIT`：只在相近素材上用光流、Morph Cut/Smooth Cut、补帧、局部视频编辑或去除接缝；不让工具改剧情事实。
- `GENERATED_BRIDGE`：单独生成可剪入的桥段，A/B 仍是独立镜头；桥段必须有自己的起止状态和消费者。
- `IN_SHOT_GENERATIVE_TRANSITION`：变化发生在一个连续生成镜头内，例如场景融合、时间流逝或风格渐变。
- `ENDPOINT_CONDITIONED`：模型实际支持并使用首尾帧/关键帧控制；必须满足下方关键帧闸门和实时能力核验。

只有需要模型生成的可见内容写入视频提示词。剪辑软件中的切点、叠化曲线、音频交叠和调色匹配写在剪辑/装配说明里，不假装模型会执行后期时间线。

### 5. 写入分镜或提示词

在当前项目使用 `video-shot-prompt-v2` 和单层镜头格式：真实切镜才新建镜头块；同一连续镜头内的形变或穿梭写成一段连续因果，不用镜内子时间段冒充多个镜头。

提示词必须写可见机制，不能只写“自然丝滑转场”“无缝衔接”或技巧名称：

- 动作匹配：写谁用哪个部位完成什么动作、方向、速度行为、切前与切后分别处于动作哪一相位；
- 遮挡：写遮挡物从哪里进入、覆盖哪些区域、何时全遮挡、打开后显露什么；
- 运镜延续：写两侧摄影机的物理移动或旋转、方向、速度行为和落点，不把 pan、truck、dolly 混写；
- 图形/尺度匹配：写匹配轮廓、屏幕位置、占画比例、焦点和透视如何承接；
- 生成式变化：写稳定锚点、唯一变化轴、变化传播路径、完成标志和变化后的正常物理状态。

生成单元看不到上一段时，正文必须自包含 B 镜需要继承的可见状态；不要写“保持上一镜一致”却不给事实或已核验引用。

### 6. 检查并局部返修

在文本阶段核对：叙事关系、两端状态、主铰链、运动方向、轴线、光色、焦点、声音、执行路线和引用资格。已有视频则按 [接镜 QA 与返修](references/qa-and-repair.md) 正常速度连看并检查接点窗口。

发现问题时修最早出错层：剪辑点不对先重选入出点；两端构图不匹配先裁切/重构图；声音突兀先修声音桥；生成中间态失真再简化变化轴或改为遮挡/硬切。不要用更强的特效叠加在坏接点上。

## 关键帧与首尾帧闸门

默认不用关键帧、真实尾帧、视频截图或关系帧作为生成输入。可以在文字方案中标记“若无关键帧路线失败，可考虑端点控制”，但在用户查看实际图片并明确通过该版本和用途前，不得把它标为 `GEN_INPUT`、上传、连入节点、同步引用或运行。

端点控制还必须满足：目标入口当前明确支持；首尾图身份、造型、人数、构图和光线相容；变化只有一个主要任务；中间运动可以由模型合理完成。换图、改图或扩大用途重新审核。内部 QA 抽帧不自动获得生产资格。

## 交付方式

小范围任务直接给出选定方案、A/铰链/B、执行路线、风险与 QA 点。批量任务使用模板逐接点列出，并标明哪些接点可纯剪辑、哪些需要生成、哪些因关键帧或模型能力待核验。

分开报告：文本设计完成、正式本地登记、远端同步/运行、实际接镜 QA、用户人工接受。任何一层完成都不能替代下一层。
