# LibTV 案例模板

这里不是只读提示词的文本库。每个案例都同时展示输入图片、进入生成链的原始提示词和实际结果视频，只有三者合看才能判断一段提示词为什么有效、哪里失败、换素材后还能不能复用。

## 从分镜角度看什么

1. 这个镜头真正要完成的观众效果是什么。
2. 提示词里的固定骨架：开始状态、动作顺序、接触或变化机制、结束状态和剪辑出口。
3. 可以替换的角色、场景、道具、台词与风格变量。
4. 模型、模式、时长、画幅、引用数量和声音条件是否兼容。
5. 结果视频只证明了什么，哪些部分仍然没有经过连续播放、声音或人工选片确认。

下面的案例与“图片素材 → 真实案例与可复用做法”是同一批 Markdown 事实源，只是这里默认突出原始提示词和分镜结构。

## 多段叙事分清三层

1. **规划层**：九宫格和分镜表决定必须有哪些信息与景别，但不直接成为正式生成输入。
2. **生成层**：节点提示词的编号时间轴决定单个结果内部怎样切镜；每段仍要有可检验的开始、动作顺序、结束和剪辑出口。
3. **装配层**：实际播放候选，选择动作语义与尾帧正确的一版，再确定入出点、字幕、片名和段落取舍。

跨段续写只继承上一条被选中结果的实际有效尾段。尾段负责人物位置、运动方向、光线、环境动态和声音连续，不替代人物标准图、场景母版或道具图。先选片再裁尾段；同一任务的另一个成功候选不能静默成为连续性来源。
