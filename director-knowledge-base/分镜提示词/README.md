# 分镜提示词知识：先判断镜头要完成什么

分镜提示词不是把剧本换成更长的形容词，而是把一个剧情任务翻译成模型能执行、观众能看懂的镜头。

## 工作顺序

1. 先说明观众在这段剧情里必须知道、感到和期待什么。
2. 区分叙事主镜、关系情绪镜、呼吸过渡镜和主观特殊镜；职责不是重要性排名。
3. 有对白、梗或情绪时，先按 [对白、梗与情绪的分镜写法](对白、梗与情绪的分镜写法.md) 明确说话意图、倾听、反应和余波，再分配时长；按职责安排摄影镜头，再组合为可生成片段。一个生成单元可以包含多个摄影镜头，连续视频不自动要求一镜到底。
4. 只选择会改变观众理解的景别、角度、构图、调度、运镜、光影和声音，不堆摄影术语。
5. 根据镜头职责决定哪些事实由人物标准图、场景图或关键帧锁定，哪些由提示词负责。
6. 写清开始状态、可见节拍、环境反馈、结束状态和剪辑出口。
7. 用 `video-shot-prompt-v2` 写成“开头引用＋全局美学设定＋逐镜相机／构图与运镜／画面”，让逐字台词、声音、动作和反应在镜内同时成立；核对整个表演的时间容量，再补必要风险边界和最小拆镜方案。
8. 按 [分镜提示词生产与交付前审查](分镜提示词生产与交付前审查.md) 在主会话检查明显剧情、连续性和执行问题；只修硬伤并复查受影响内容，没有大问题即可继续。默认不创建审查子代理或逐维评分表。

新建分镜或明确要求全面重设计时，先从当前剧情、用户决定、台词与连续性事实完成新设计，再用旧提示词检查回归。仅修局部问题且输入稳定时，先核对当前提示词与已冻结设计，保留有效选择，只修改受影响单元及相邻连续性；发现上游错误才重开对应设计。只读审查不自动创建替代稿。

镜头包含逐字对白、OS/VO、喜剧节拍或情感落点时，继续读取 [对白、梗与情绪的分镜写法](对白、梗与情绪的分镜写法.md)，把说话、倾听、潜台词、表演节拍和真实时长一起写进分镜。

方法要落到实际选择。在已有导演设计或分镜执行表中，把会影响本场的关键方法连接到“本镜怎样拍、为什么、正文哪一镜体现”，例如反应镜如何改变观众理解、声音桥为何触发切换、机位为何与场景参考相容；不用另建知识使用流水账。打开过文档、列出摄影名词或自动填满评分表都不能证明应用。

先完成本地正式分镜、台词合同、正文和索引，并在素材中心页面核对当前版本，再创建或更新 LibTV。完整顺序遵守仓库 `AGENTS.md`；远端画布不能领先于本地故事事实。

镜头包含手机屏幕、文件、卡片或工作牌等可读信息时，读取 [导演设计方法](导演设计方法.md) 的“互动主镜与可读插镜分责”，并同时读取图片域的 [关系关键帧与连续性帧](../图片素材/关系关键帧与连续性帧.md)。关系帧按角色视线和动作摆放道具；观众读字使用角色 POV、越肩或局部插镜，不为可读性强迫道具朝摄影机。

## 输出给用户的《分镜执行表》

| 字段 | 用户需要看到什么 |
| --- | --- |
| 镜头编号 | 对应哪段剧情 |
| 剧情作用 | 观众在这一镜必须看懂什么 |
| 镜头类型 | 为什么选择这种镜头 |
| 导演设计 | 只列对本镜有用的景别、角度、构图、调度、相机、光影、声音和剪辑决定 |
| 时长 | 暂定时长或目标模型的实际时长 |
| 图片参考 | 使用哪些现有图，还缺什么图 |
| 分镜提示词 | 可以直接进入生产的最终文本 |
| 生产前检查 | 主会话检查范围、明显硬伤或无硬伤、必要修复与结论；详细评分仅在用户要求时提供 |
| 失败时怎么拆 | 任务过载时的最小拆镜方案 |

设计完整分镜、镜头职责未定或需要比较机位方案时，先读《导演设计方法》；所有提示词创建、重写或生产前审查都必须读取《分镜提示词生产与交付前审查》。单个镜头的类型和导演选择已经冻结时，只减少额外的专项说明或案例，不能跳过审查门槛。不要为了“完整”把所有镜头类型和案例一起塞进上下文。
