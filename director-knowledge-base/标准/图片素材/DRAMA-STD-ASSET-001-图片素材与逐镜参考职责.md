# DRAMA-STD-ASSET-001｜图片素材与逐镜参考职责 v0.1.1

## 适用范围

本标准用于从短剧剧本、场景或镜头目标推导需要生成、验收和引用的图片素材。它覆盖具名人物、群演、怪物、场景、道具、状态变化、构图关系和连续性，不规定固定参考图数量。

项目当前将本标准作为 `ACTIVE` 规划基线。证据成熟度为 `REUSABLE`，尚未通过两次自有成片人工接受，因此不构成质量保证。

## 输入

- 当前剧本、世界观与类型合同；
- 角色、场景、道具和状态连续性；
- 目标画幅、模型、时长和实时媒体预算；
- 已有资产的实际文件、版本、状态与验收结果；
- 每个 generation unit 的可见事实、动作关系和主镜头类型。

缺失画幅不会阻止画幅无关的资产规划，但会阻止依赖构图与安全区的图片定稿。

## 决策规则

### 1. 先区分母版、内部参考和直接输入

- `MASTER`：可复用事实源，例如 `IDENTITY_AVATAR`、对应造型三视图、场景圣经和道具结构母版。
- `INTERNAL`：服装/饰品说明、风格图、比例尺、平面图、宫格和带标注设计板；默认零视频生成入边。
- `DIRECT_INPUT`：从已验收母版派生、面向某个模型和镜头范围的干净输入；不得静默改变母版用途。

### 2. 素材类型与产物标准

| Asset type | 主要职责 | 必须包含 | 默认禁止 |
| --- | --- | --- | --- |
| `IDENTITY_AVATAR` | 脸部身份 | 清楚正脸；按需要含 3/4、严格侧脸 | 戏剧场景、强光效、其他人物 |
| `CHARACTER_LOOK_TURNAROUND` | 当前造型体型与前侧背结构 | 同一造型的全身正面、严格侧面、背面，脚部完整 | 换装、不同伤情、动作过程 |
| `CHARACTER_COMPOSITE_DIRECT_INPUT` | 一人一文件压缩身份和当前造型 | 大正脸与侧脸/3/4，加全身正面、严格侧面、背面 | 文字、编号、网格、水印、其他人物、场景 |
| `CHARACTER_STATE_VARIANT` | 未戴/手持/已戴、受伤前后等剧情状态 | 每个版本只含一个明确状态并可追溯同一人物母版 | 多种状态混在同一输入且职责不明 |
| `COSTUME_DETAIL_INTERNAL` | 服装、鞋袜、发饰、材料设计 | 足够解释造型制作的局部和版本 | 默认直接接视频 |
| `CREATURE_STRUCTURE` | 怪物轮廓、附肢与体型 | 能解释角、翼、尾、异形躯干的正侧背或关键角度 | 只给难以辨形的戏剧远景 |
| `CROWD_ARCHETYPE_SHEET` | 群演人数与造型差异范围 | 多种非具名人物的全身类型和差异 | 复制具名主角作为群演 |
| `STYLE_REFERENCE_INTERNAL` | 视觉语汇与材质家族 | 风格、光色或形态母题 | 承担具体角色、剧情或站位事实 |
| `SCENE_BIBLE_INTERNAL` | 空间、材质、色彩、时间天气设计 | 主视图、布局、结构和阶段变化 | 默认直接接视频 |
| `CLEAN_SCENE_PLATE` | 镜头可用空间和光向 | 无文字的清楚空间、入口、纵深和走位区域 | 无关人物、错误招牌、拼板 |
| `PROP_STATE` | 道具形状、持握和状态 | 关键角度及开合、损坏等状态版本 | 多个无关道具错误绑定 |
| `SHOT_KEYFRAME` | 景别、机位、站位、视线与终态构图 | 当前人物/状态/道具和明确画面关系 | 把身份职责完全交给远景人物 |
| `INTERACTION_POSE` | 骑乘、拥抱、压制、搀扶和接触 | 身体重心、接触点和遮挡关系 | 用中性人物板替代复杂关系 |
| `SCALE_REFERENCE_INTERNAL` | 主体体型关系 | 可比较的尺度或同构图关系 | 未派生就直接输入带刻度文字的板 |
| `CONTINUITY_FRAME` | 前镜站位、光色和动作起点 | 已验收、状态正确、无污染的实际帧 | 水印、字幕、错误道具、严重模糊 |

### 3. “人物只能一张图”的硬标准

允许使用 `CHARACTER_COMPOSITE_DIRECT_INPUT`，但必须：

- 一张图只出现一个具名人物、一个连续性造型和一个伤情状态；
- 大尺寸正脸，最好含严格侧脸或明确 3/4；
- 头到脚的正面、严格 90° 侧面、背面全身；
- 各视图身份、年龄、体型、发型、服装、配饰、伤情一致；
- 中性干净背景，无文字、编号、箭头、格线、Logo、水印、场景和动作过程；
- 仍保留项目要求的身份头像与对应造型三视图母版；复合板只是派生的 `DIRECT_INPUT`；
- 用近景和转身代表镜头实际播放，检查重复人物、拼板和影棚背景泄漏。

如果严格侧面缺失，只能在正面/3/4 主导且代表试片通过的限定镜头范围使用，不能把它提升为通用母版。

### 4. 逐镜最小职责集

| 镜头任务 | 默认图片职责 |
| --- | --- |
| 空间建立/氛围空镜 | 干净场景；必要时加关键道具或风格派生件，不接无关人物 |
| 单人表演 | 当前人物复合输入 + 场景；手持物重要时加道具 |
| 双人对白 | 两人各自当前造型输入 + 场景；构图困难时加关系关键帧 |
| 拥抱/骑乘/压制/接触 | 人物输入 + 场景 + `INTERACTION_POSE` 或 `SHOT_KEYFRAME` |
| 追逐/打斗 | 每个可见主体 + 场景 + 各自关键武器；按需加开场构图、尺度、前镜帧 |
| 状态转换 | before + transition（需要时）+ after + 场景；逐阶段绑定职责 |
| 道具操作/特写 | 道具状态 + 操作者；仅当空间参与剧情时加场景 |
| 群体编舞 | 领舞人物 + `CROWD_ARCHETYPE_SHEET` + 场景/阵型关键帧 |
| 连续下一镜 | 干净 `CONTINUITY_FRAME`；人物太小或转面时仍补人物身份/造型 |
| 定向修复 | 实际失败或有效帧 + 只与失败原因有关的资产 |

## 输出合同

输出 `AssetPlan`，其中每个资产至少记录：

- `assetId`、`assetType`、实体与连续性状态；
- `scope: MASTER | INTERNAL | DIRECT_INPUT`；
- 故事职责、必须和禁止内容、来源与版本；
- `status: EXISTING_ACCEPTED | NEEDS_INSPECTION | MISSING | DRAFT | CONFLICT`；
- `usedBy` generation unit 列表；
- 图片验收与失败信号；
- 使用的标准和知识卡。

同时输出逐镜 `ReferenceResponsibilityMatrix`，并把“资产是否存在”和“生产处置”分成两个字段。每个可见具名人物至少声明身份、当前造型和三视图职责；三视图的 disposition 必须是 `CONNECTED`、`NOT_APPLICABLE`、`BUDGET_EXCLUDED` 或 `CONFLICT`。若需要的三视图尚不存在，写 `asset: MISSING`、`disposition: CONFLICT` 和缺失原因，不能把 `MISSING` 当成三视图 disposition。其他职责在 DRAFT 分析中可以使用 `disposition: MISSING`，但镜头不得标为 prompt-ready。

## 验收

- 实际打开每张图，不根据名称、上游 prompt 或任务成功判断内容；
- 主体身份、造型、体型、附肢、道具和状态在图内自洽；
- 直接输入无文字、网格、Logo、水印、无关人物和错误场景；
- 每项可见事实有唯一主要职责，所有 Node/asset ID 与实际内容一致；
- 参考预算内是最小兼容集合，超限项有明确 `BUDGET_EXCLUDED` 原因；
- 代表视频实际播放通过相应转身、近景、接触、群体或状态风险后，才扩大使用范围。

## 停止条件

- 角色、造型、状态、场景或道具事实互相冲突；
- 具名人物缺身份头像或当前造型三视图母版；
- 引用职责缺失、重复或映射到错误实际资产；
- 只有带字/网格/水印的内部板，尚未派生干净输入；
- 模型媒体预算超限且排除选择会改变镜头；
- 未经代表试片就准备批量直接输入新的复合板、三视图格式或群演板。

## 证据与成熟度

- `policyStatus`: `ACTIVE`
- `evidenceStatus`: `REUSABLE`
- 主要证据卡：`DRAMA-PAT-101`、`DRAMA-PAT-102`、`DRAMA-PAT-103`、`DRAMA-PAT-104`、`DRAMA-PAT-105`、`DRAMA-RISK-101`
- 未验证：竖屏构图适配、跨模型污染率、自有成片中的两次人工接受。
