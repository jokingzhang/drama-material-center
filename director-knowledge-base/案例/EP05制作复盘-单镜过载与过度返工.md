## 反例一：把“连续的视频”变成“全程不切镜”

### 发生了什么

用户先指出旧 7 秒揽肩段“肘击像打人”，并提出与后面的 11 秒官宣做成一个连续视频，让动作更连贯。原任务进一步承诺“揽肩、轻碰、官宣全程不切镜”，随后把执行表写成“用户要求……18 秒连续镜头”。这一步把助手选择的一镜到底形式写成了用户要求。

用户给的截图与 `EP05-S03-U01-VIDEO-SHOT-PROMPT-v15.md` 正文相符：Wan 3.0、9:16、1080P、18 秒，固定双人中景，一张真实揽肩完成态图片加一条声音参考。正文明确写“没有切镜、变焦或重新摆站位”。

![用户提供的18秒单镜提示词截图](/knowledge-media/EP05-retro-20260905/prompt-overloaded-single-shot-v01.png)

同一镜头被要求依次完成：

| 时间 | 要求观众读到什么 |
| --- | --- |
| 0—1 秒 | 揽肩接触成立、女方肩背一僵 |
| 1—3.5 秒 | 转头、瞪视、克制抗拒 |
| 3.5—4.2 秒 | 腰侧小幅肘部轻碰及收回 |
| 4.2—7.5 秒 | 收住抗拒、转回视线、准备官宣 |
| 7.5—15 秒 | 完整官宣、清楚口型，同时读出女方听到关系称谓的反应 |
| 15—18 秒 | 三秒死寂、表情余波，同时保持原揽肩姿态以衔接耳语 |

为了同时看清两张脸、腰侧肘部和搭肩手掌，构图扩大到头顶至髋下；又要求这些细节全程清楚、人体朝向固定、接触不断。信息都“在画面里”不代表观众能按顺序读清，也不代表模型能同时维持每项约束。

### 实际结果与不能推出的结论

- 合并视频 `v03` 的原 QA 记录：约 5.5—7 秒女方转动躯干，男方官宣前松开左手，到片尾仍分开；记录为 `HARD_REJECT`。
- 后续用该片另行检查过的 3 秒揽肩有效帧重做输入，并反复强调左掌持续搭肩。视频 `v04` 的原 QA 仍记录：约 6 秒离肩，9 秒时手臂已放下；抗拒动作变小，但前臂动作也没有按所写肘部执行。
- `v04` 是 `USER_EDIT_SELECTION_PENDING`。用户已停止生成、准备试剪，不能把保留候选说成“持续揽肩修复成功”。耳语段当时尚未运行。
- 上述 QA 等级是原任务记录，不是本轮重新拒收。松手本身不构成普遍硬伤；若实际剪辑后人物关系与后续接镜仍成立，就不应仅为满足“始终搭肩”的文字追加生成。用户停止后，先用现有候选试剪。
- **导演判断**：这个设计用固定构图和大量保持姿态的文字承担过多任务。两次 1080P 结果仍丢失接触，说明本例没有靠提高分辨率解决问题；没有受控对照，不能据此证明单镜时长是唯一原因，或断言某模型普遍不能拍长镜头。

### 应当怎样设计

先区分三个层次：生成单元是一次模型任务输出的视频片段；摄影镜头是其中一个机位和构图组织的连续画面；最终连续性是观众看到的人物、动作、空间和声音能否接上。用户要求连续，不能自动解释为禁止切镜。

本例可以先按下列职责设计，具体时间依对白和表演容量确定：

1. **接触与抗拒**：双人关系镜交代揽肩，再让短小轻碰表达无声提醒，清楚控制受力和对方反应。
2. **公开官宣**：以说话者为视觉重点，完整原句和声音连续；听者不必在同一较宽画面内承担所有微表情。
3. **关系落下后的反应**：切女方反应或回到双人关系，保留完整三秒静默；在必要的回镜中核对接触仍成立。

若当前入口支持多镜头，可以把这几个镜头放在一个生成单元内；若关键接触仍不稳定，再按最小戏剧边界拆成多个单元，用已核实实际画面和声音续接。这里是设计建议，未生成对照验证，不是固定三镜、固定时长配额，也不要求每一帧都展示同一接触点。

上述讨论是复盘时的一般导演判断，不构成当前工作流的单镜豁免。**后续用户明确决定：“多个镜头是硬要求”，不能再用一个时间＋镜头标题承载整段长描述。** 当前每个待生产单元因此至少要有两个独立计时、实际切换的完整镜头块；单个动作仍可在其中一镜内连续拍清，不能据此将整个单元写成一镜到底。已有可用或用户认可的视频保留，不因新格式规则追加生成。

## 反例二：首个开场已够用，仍追求理想接缝

### 区分生成、失败与本地版本

`EP05-S01-U00` 的运行回执和导出计划记录如下：

| 记录版本 | 发生的操作 | 结果与费用证据 |
| --- | --- | --- |
| v01 | 首尾帧模式提交 6 秒任务 | 失败、没有视频；平台提示积分会在 2 小时内返还，未核实退款到账 |
| v02 | 再次提交首尾帧模式 | 同样失败；同样提示退款，不能直接认定最终损失 |
| v03 | 混合参考模式生成 6 秒开场 | 首个成功出片，即交付包里的“开场初版”；用户本轮认为这一版即可 |
| v04 | 为更精确连接首条，另生成由厅内向外退镜的 6 秒素材 | 新的成功生成任务；相对用户认可的首版，这是可避免的额外生成 |
| v05 | 对 v04 本地倒放，环境声保持正向，末帧换为下游真实首帧 | `NO_NEW_GENERATION`；继承 v04 的任务 ID，不是第五次模型生成 |

共有四个不同生成任务 ID，两个失败、两个成功；不能按五个版本算五次收费。本页不估算实际扣分或把退款提示当作到账凭证。

原任务认为 v03 结尾推进过近，遂选择“反向生成＋本地倒放＋末帧锚定”。这个方案能改变接缝，却引入了新生成与额外处理。用户后来明确认为首个出片已足够，说明此处采用了高于实际用途的内部标准。

### 以后怎样停下来

- 开场的用途先按“建立地点并能接入主戏”判断。与理想首帧的像素、机位或大小差异，不自动成为剧情或剪辑硬伤。
- 怀疑跳切时，先用真实片段试一个合适的入出点，检查实际组接。能通过切点、轻度裁切或声音连接解决，或者偏差不影响理解，就保留首个可用结果。
- 只有具体时间点上的问题使当前故事或明确交付约束无法成立，且现有片段没有合理修复办法时，才在已有授权和预算内考虑新生成。用户已接受后停止可选返修。
- 反向生成再倒放只是一种有条件的工具：本例没有主要台词或明显不可逆动作，仍记录了背景宾客动作倒放；不能推广到说话、行走、开关门、递物等镜头，更不能把它变成普通开场的默认步骤。
- “先生成全部，没有大问题不要停”授权推进制作，不是为每条片反复追求最佳版本的指令。

## 其它值得保留的经验

| 问题或做法 | EP05 的具体证据 | 可复用的判断 |
| --- | --- | --- |
| 动作完成了，但情绪语义错了 | 原任务判断肘部动作成立，用户仍认为像打人 | 检查观众会理解为提醒、抗拒还是攻击；一起描述幅度、速度、接触位置、反作用和声音。“轻轻”不能单独抵消攻击性的动作及反应 |
| 静态接触帧不能维持未来接触 | 揽肩 v04 从正确接触帧开始，之后仍松手 | 图锁定起始可见关系，不是未来 18 秒的动作控制器；反复失败时重新分配镜头职责，不只追加保持姿态的文字 |
| 切镜后空间翻转 | 入厅 v01 约 5.8 秒后的背面镜，把入口复制到前方；v02 的实际门线从身前经过、最后在身后 | 固定摄影机物理侧、可见门槛和进入完成态；是否严格按计划锁机位属于次要，真实方向和因果成立才重要 |
| 实际生成状态应服务后续镜头 | 首条实际有奶奶站坐变化、霍景明左手持杯；用户接受庆寿背景并要求注意后续连续性 | 继承已采用片段的真实可见状态；用户接受某一项只覆盖该项，不代表全部镜头和声音已验收 |
| 局部裁切比整条重跑合算 | 走近片段排除了错误站位的奶奶；反应片段排除了换手的杯子；跟随片段排除了凭空出现的手包 | 只有错误完全在可舍弃区域，且必要动作仍可读时才裁切；记录清晰度和取景损失。裁切是剪辑修复，不能据此声称原生成已正确或拿错误原帧继续生产 |
| ASR 辅助不能代替试听 | “旁支”曾被小模型转成“螃蟹”，较大模型给出同音结果；原 QA 仍保留主观试听未核实 | 不给识别器预塞目标台词；同音或转写歧义不独自触发重跑。对白完整、音色、情绪和混音是不同检查 |
| 模型 schema 与本次链路成功是两回事 | 开场首尾入口两次失败，混合入口随后出片；失败信息没有给出具体根因 | 保存失败类别与实际入口，停止无新依据的同设置重试；不能由此宣布 Wan 永久不支持首尾帧 |
| 审查与运行校验也会过度 | 原任务经历独立审查、局部返修与节点装配，用户随后要求主会话自行检查 | 主会话只拦截明显硬伤；Node 等价替换做执行校验，不重做语义评分；仍保留本地先更新及每次运行前回读 |
| 接手与交付要区分状态 | 接手任务先用已有跟随原片做局部修复；用户叫停后耳语未运行，交付包保留 19 个不同视频供试剪 | 先核对已完成任务及版本，避免重复生成；素材包齐备不等于整集完工，停止生成不等于选中所有候选 |
