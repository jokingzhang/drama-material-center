# LibTV 分镜提示词对照研究：哪些话该删，哪些事必须说清

研究日期：2026-09-07。范围：用户截图红框中的 14 个项目，其中 13 个为外部案例，《限时婚约｜逃婚新娘红果版》以本地正式绑定的 EP09 为对照。

**结论：有明显改进空间。当前问题首先出在任务打包和模板落地：大量篇幅用来重复约束，真正的镜头选择被埋在里面。不能用统一缩短字数解决，也不应把好项目中的每个节点当成正确范本。**

本轮只读 LibTV、使用已登录 Chrome 查看画布及播放代表片段，保存研究报告和原始证据。未修改当前 EP09、正式业务索引、Skill、模板或远端节点，未运行媒体生成。报告中的调整均为建议，尚未证明能提高目标模型的生成成功率。

## 2. 三个实际播放样本

### 《让他们再失望一次》：参考图承担静态事实，文字承担变化

节点 `02cd1872-8337-4f76-867e-914f56c23adc`，页面名“静帧18_KlingO3_3s”。主文 224 字符，当前界面为 Kling O3、3 秒、16:9。画布中首帧与视频相邻，画面均为透明伞下低头的短发女子。

当前文字集中要求保持低头、伞面水珠滑落与发丝微动，实播可见人物和构图保持稳定、伞面水迹变化。该样本的优势是任务集中，首帧已承担人物、服饰、场景和光色的大量信息。它不能证明这些静态事实对没有合适首帧的任务也可以全部省略。

此外，当前界面中第二个输入槽显示为“尾帧”，缩略图为人物标准图；没有把这套装配方式判定为合适，也没有完成末帧污染专项验收。**可学的是按输入职责写增量变化，不是照搬它的参考接线。**

### 《无尽蝉鸣的盛夏》：通过物件和停顿让情绪发生

节点 `v-WgX9imjdxZ`，主文 2742 字符，实际播放器时长约 15.09 秒。播放中观察到：庭院建立后人物入画，约 5.6 秒为取西瓜的手部，约 8.3 秒为咀嚼近景，约 11 秒保持面部停顿，约 13.6 秒切风铃。

可取的是观众注意力的顺序：**环境与物件 → 人物动作 → 面部变化 → 外界刺激**。情绪由具体行为承载，背景物件也参与了节拍。这比只给“自然、细腻、克制”的表演标签更可执行。

但当前提示词自身存在环境与声音段落重复、画幅口径冲突。未试听音轨，所以“风铃声音是否准确触发人物反应”保持未验证。不能把该样本包装为全部指令逐秒兑现的成功案例。

### 《今天不宜约会》：短输入框后面还有完整分镜

节点 `v-lVHvtVPZs7`，页面名“视频节点 182”。主文 117 字符，关联 `t-TFuFHpRxHm` 含 1372 字符的八段分镜。实际播放器 25.056 秒。

关联文字按戴手套、抬眼、输血管、器械、医生操作、监护仪、汗与眼神、全景收尾组织。实播约 4.4 秒为医生与病人，8.4 秒为输液局部，12.4 秒为操作与递接，16.4 秒突出监护仪，20.4 秒为医生眼部，24.4 秒为空手术室。

它说明“视线应当依次落在哪里”可以由镜头对象组织出来。也同时暴露了一个不能忽略的问题：当前文字末镜要求医生和团队在场，结果尾段却为空室。这一差异足以要求核查原始生成版本及选片范围；**不能直接宣布当前节点已按文字完成，更不能用漂亮画面覆盖剧情完成态差异。**

此例研究的是影视表达，不构成医疗操作正确性的评价。

## 3. 本地问题定位：知识库方向是对的，执行没有贯彻到底

本地《导演设计方法》开篇就要求“只保留会改变观众理解、表演调度或生成结果的选择”；《对白、梗与情绪的分镜写法》也明确要求删掉重复解释，让反应和后果成立。问题不能全部归给豆包写作能力。

### 3.1 本次 EP09 的任务打包主动诱导了扩写

EP09 创作记录中的 `jobs.py` 第 9 行明确写入：

> 建议1500—2100字

而模板正文和模板目录都写明不为凑长度扩写，不设固定最终字符门槛。这个下限是主会话打包时额外加上的，不是用户要求，也不是模板要求。**这是本次执行错误，应先纠正任务简报。**

正式绑定的 EP09 共 14 份提示词，字符数范围 1310—1887，中位数 1517，总计 21272 字符。各段正文合计 20169 字符，其中：

| 段落 | 字符数 |
| --- | ---: |
| 风格 | 1112 |
| 空间与轴线 | 2543 |
| 时间轴 | 6656 |
| 声音 | 1898 |
| 参考 | 5271 |
| 禁止 | 2689 |

参考与禁止合计约占段落正文 **39.5%**。这不表示其中 39.5% 都是废话：人物身份、造型、声音和道具职责确实需要说明。但当前多个单元逐项重复大段通用句，稀释了每镜真正不同的部分。

### 3.2 模板将动作场的概念套进了普通生活场

`video-shot-prompt-v1.md` 第 7 行要求写入口、出口、危险侧、安全侧。EP09 工作室打电话单元 U304 因而写出：

> 画面危险侧为画右拱窗外强光过曝区域，安全侧为画左室内阴影过渡区。

这是没有剧情用途的分类。照明风险与人物行动中的危险方向不应混为一谈。本镜真正需要的是窗光方向、人物与桌面手机的位置、拍摄侧，以及屏幕不展示号码。

建议把入口、出口、危险边界改成按镜头任务出现的条件项。普通对白仍应说清必要地理，但不需要给每个空间编造危险侧。

### 3.3 参考职责解释过长，部分规则在为固定句式服务

模板和 runner 要求每项参考在指定范围内出现职责关键词，三视图要带限定和不复制排版的边界；`validateReferencePlanOutput` 还要求引用只出现在参考段，禁止在时间轴中再次出现。

需要保留的是：真实资产对应谁、当前造型是什么、主要职责是什么、是否与其它输入冲突。完整路径、哈希、验收来源、历史版本及人工检查步骤应由已有引用计划和创作记录承担。

可以评估将同一生成单元内通用的“标准图版式不进入画面”合并说明，避免每个人重复整段。但不要误以为写了“只参考脸”就能隐藏冲突像素；素材相容性仍须在写提示词前处理。

外部案例常把 Node 引用直接放在动作主体附近。本地禁止这种写法是格式设计选择，不是普遍的模型规律。若将来采用内联引用，须同步调整 runner 与引用回读检查；本轮不擅自更改现行约定。

### 3.4 对人负责的交付说明进入了模型正文

例如 U304 中的“江砚秋对白时间窗与时间轴一致”、D17 和 U305 制作编号、后续抽取真实帧的检查要求，主要服务制作和验收。视频模型不需要读一遍我们已经如何核对合同。

建议复用现有文件分工：

| 信息 | 更合适的承载位置 |
| --- | --- |
| 观众必须看懂什么、这一镜的关系变化、回退拆法 | 导演设计与执行表 |
| 逐字对白、说话人、时间、意图、声音职责、嘴部及听者反应 | 对白合同；生成正文保留该镜实际要表演的部分 |
| 资产路径、版本、哈希、状态、编号与节点映射 | 引用计划和业务索引 |
| 本镜的画面、动作、表演、对白、声音、开始与结束状态 | 模型提示词 |
| 后期文字、叠层、跟踪、合成验收步骤 | 已有后期执行说明；模型正文仅保留所需干净表面和拍摄边界 |

**每个生成节点仍必须自包含。** 不能把必要的角色映射、造型、声音和场景条件移出后，假设模型会读取未提交的全局合同。分层是去掉制作旁白，保留该节点实际需要的条件。

### 3.5 “说了很多”仍可能缺少观众看到关键事实的保证

EP09 U102 的前 5 秒安排了“下班”对白、霍景深跨身放回手机、江砚秋让出手臂空间、准备掀被，以及江砚秋发现霍景深眼下倦意；机位为双人中景兼顾外侧桌。

台词、动作和归属并非缺失，但**观众具体在哪一拍看清疲惫证据**没有足够突出的安排。接下来的中近景又主要拍江砚秋提问。风险在于观众只听到“你一晚上没睡好”，没有先读到触发关心的发现。

这里应回导演设计层确定“放手机完成 → 发现疲惫 → 关心出口”的视觉优先顺序；可以用停顿、视线切或适当景别解决，不应仅追加“倦意明显”或更多全名、形容词，也不必默认新增关键帧。

反过来，U203“道歉不能一笔带过”的核心设计已经有价值：霍景深道歉后留白，江砚秋没有立即软化，反问后再切霍景深停住辩解并看向袋口。这里的说听、阻力与后果应保留，不能为了变短删掉。

### 3.6 审查能发现规则错误，还需要判断信息是否突出

当前 Skill 要求十四维度评分，核心摄影、动作等维度达到 2 分；同时把每次操作主体都写全名作为硬条件。EP09 的 14 份提示词共出现 533 次具名人物全名。

这些规定有防止归属歧义的用途。但“每项都有文字”“每次都写全名”不自动保证读者能抓住事件。当前全名规则可能来自明确历史偏好，不能为省字自行推翻；可以先通过合并相同信息、减少制作旁白降低重复。

建议 Reviewer 先只读生成正文，用三句话复述：开场是什么状态；什么动作或话引起了谁的变化；结束留下什么状态。再与导演设计和事实合同核对。遇到缺失或歧义，指出具体时间段和理解后果；避免只追加通用禁令。

## 4. 建议先改写作方法，再决定是否换模板

优先保留目前 v1 的五段结构，先调整任务打包和段落职责；不急着引入一套更复杂的新模板。

| 部位 | 建议变化 | 应保留的内容 |
| --- | --- | --- |
| 给豆包的任务 | 删除“建议写到多少字”，明确本镜主要信息和最容易漏掉的一项；不要把所有检查项变成逐段扩写指令 | 冻结事实、对白、动作与时长、参考职责、有限创作空间 |
| 风格 | 用短段统一画幅、时长、视觉基调与节奏；已由相容参考充分提供的细节少重复 | 会影响该节点实际画面的风格与光色条件 |
| 空间与轴线 | 只写本镜实际需要的站位、摄影机侧、道具归属；边界动作才展开进出和完成链 | 可见动作不能跨错侧，人物、物件不能凭空换位 |
| 时间轴 | 作为正文中心，按“触发 → 行动或说话 → 听者反应 → 结果”推进，镜头选择服务注意力 | 原句、说话人、合理时间与反应空间；必要的开始和结束状态 |
| 声音 | 写当前段真实发生的声音及职责，避免把“无某某”在多个段落重复 | 固定音色或一次性原生声音的角色归属、必要音效与声音桥 |
| 参考 | 每个真实输入对应一项明确职责；合并同一单元内可合并的通用解释 | 输入顺序、角色映射、当前造型、兼容性和重要边界 |
| 禁止 | 只留当前镜头高概率且正向写法不能充分防住的重大错误；删除对正文的复述 | 错误会改变人物、因果、道具归属或交付结果的约束 |

不设新的统一 300 字、800 字或百分比目标。三秒微动、双人接话、多人递接和长镜调度需要不同信息量。每句话都应该能回答：它具体改变哪一处可见、可听或可验证的结果？

### 需要区别对待的四类任务

1. **已有合适首帧的单镜微动**：集中写新增动作、相机变化、声音与收尾；不重造静态世界。
2. **对白与反应**：重点是话为什么说、对方怎么接、停顿留在哪里、观众看谁；不用复杂运镜填充。
3. **接触、递接、过门与多人调度**：重点是主体、顺序、物理侧、接触与完成态；不能为了精简删掉动作链。
4. **信息揭示和情绪转折**：明确观众何时看到信息、何时看到人物反应，减少抽象情绪标签；文字画面用已有后期合同处理。

这些是内容选择方式，不要求新增四套文件模板。

## 5. 哪些调整能直接做，哪些需要协同改规则

以下为后续实施建议，本报告没有执行规则变更。

| 优先级 | 调整 | 涉及文件或职责 | 验证方式 |
| --- | --- | --- | --- |

| P1 | 独立文本审查先判断能否看懂，再检查完备性 | `review-mode.md` 与分镜预审方法 | 必须给出具体冗余或遗漏证据，不以字数短作为通过理由 |
| P2 | 评估内联 Node 引用和对白正文去重 | runner、模板目录、项目生产规则、根 AGENTS 对白约定 | 一次性同步规则后再验证；当前仍按现行合同执行 |

尤其是“对白只出现一处”不能单改模板：根 AGENTS 要求时间轴与声音说明均出现逐字台词。这一项即使有减少重复的空间，也需要先作明确规则决定，然后同步校验与工作流，不能静默绕开。

后续如要验证改善，应先选三种现有任务：一个普通接话镜、一个带道具状态变化的镜头、一个情绪转折。主会话重新冻结导演选择，豆包据此返回精炼完整的新版本，保留原文和旧版，交全新只读 Reviewer 对照事实与表达。文本通过后，生成效果仍要靠另行授权的试片检验；本轮没有执行这一步。
