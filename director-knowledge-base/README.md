# AI 导演知识库

这是 AI Director 的项目级工作手册，由 AI 负责维护。用户不需要整理文档、登记知识卡或理解内部数据结构，只需要查看创作结果并确认会改变故事方向的决定。

知识库只回答三个问题：

1. **剧本知识**：一个想法怎样变成能拍的故事；已有剧本哪里需要补强。
2. **图片素材**：这部剧应该准备哪些图片，每张图片应该长什么样。
3. **分镜提示词**：每段剧情属于什么镜头任务，应该怎样拆镜和写提示词。

## 使用顺序

```text
想法、故事梗概或剧本
        ↓
读取「剧本」：补全故事并让用户确认关键方向
        ↓
读取「图片素材」：形成图片素材清单与每张图的标准
        ↓
读取「分镜提示词」：确定镜头职责和导演设计并形成分镜执行表
```

AI Director 每次只读取当前问题需要的文档：先读本页，再读一个领域入口，随后只打开相关主题文档。案例与来源只在需要示例、反例或依据时继续读取，不默认加载全部研究材料。

LibTV 的可复用镜头采用“一份案例、两个入口”：物理文件只存放在 `案例/可复用镜头/`，每份必须同时包含输入图片、原始提示词和实际结果视频；“图片素材”入口突出图片职责，“分镜提示词”入口突出动作骨架和替换方法。两边看到的是同一份事实，不各自复制半份案例。

## 三个入口

- [剧本知识](剧本/README.md)
- [图片素材知识](图片素材/README.md)
- [分镜提示词知识](分镜提示词/README.md)
- [完整镜头案例的事实源](案例/可复用镜头/README.md)

## 用户最终看到什么

- 输入是想法或未完成稿：先看到一份容易判断的《故事方案》。
- 故事方向确认后：看到《图片素材清单》，说明做什么图、标准是什么、用在哪里。
- 进入镜头设计后：看到《分镜执行表》，说明剧情作用、镜头类型、必要的导演选择、参考图片和最终提示词。

不向用户展示知识 ID、成熟度字段、JSON Schema、索引校验或接口状态。

## AI 怎样维护这里

- 新案例先保存在 `案例/` 或 `来源/`，保留事实、推断和未知。
- 只有“输入图片 + 原始提示词 + 实际结果视频”齐全的链路才进入 `案例/可复用镜头/`；缺一项的仍可作为研究证据，但不包装成可直接套用模板。
- 能合法下载的代表视频存入 Git 忽略的 `director-knowledge-base/.media/` 供本地网页播放；下载失败时保留画布、节点和远端来源，不阻塞其他案例，也不伪造本地视频。
- 只有案例确实改变了工作方法时，才修改对应的剧本、图片或分镜主题文档。
- 更新主题文档时用大白话写清楚：什么时候用、需要什么、怎样做、常见失败、参考案例。
- 不需要中央 JSON 索引、知识 API、分析注册或 `knowledgeUsed` 账本。
- 当前项目事实和用户明确决定始终高于通用经验。

旧的标准、知识卡、证据账本和来源登记仍作为研究档案保留，但不是 AI Director 工作的前置条件。
