## 方法与证据边界

- 使用 LibTV CLI 按画布 UUID 和唯一 node key 回读；没有修改节点、连线、提示词或运行任务。
- 实际查看代表图片；代表视频完成全流解码并抽取多时点画面。部分节点只完成结构与提示词回读。
- 本轮没有建立七个画布的完整“生成节点 → 最终剪辑”映射，也没有获得创作者逐镜人工验收记录。
- 受本机锁屏和来源限制，没有完成全部样本的连续播放与主观试听；技术解码、抽帧检查和人类成片验收必须分开。
- 来源副本中存在水印、历史候选、废弃分支、上传成片和后处理节点。画布整体不能被当作统一的优质答案。

## 总体结论

1. 参考图数量不是固定标准。先声明身份、当前造型、场景、道具、构图、接触、状态变化和连续性职责，再选择最小兼容集合。
2. “一人一图”在多个案例中指一张人物复合板，而不是一张戏剧照；复合板仍不能替代场景、构图或动作关系图。
3. 镜头必须先按叙事任务分类，再使用对应的必填控制项。建立、对白、接触、打斗、变身、蒙太奇、仪式和续接修复不能只靠同一个通用段落。
4. 提示词长度不是质量代理。事实矛盾、角色映射错误、节拍超载和时长未覆盖是跨案例反复出现的硬失败。
5. 同一个案例必须把图片、原提示词和实际视频放在一起；只看图片无法知道它是否参与了目标动作，只看提示词也无法知道模型实际执行了什么。
6. 这七条只形成可参考的工作方法，不构成当前项目的成片质量保证；是否采用仍要结合当前模型、素材、实际播放和用户选片。
