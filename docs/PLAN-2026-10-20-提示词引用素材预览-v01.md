# 提示词引用素材预览方案 v01

日期：2026-10-20。状态：已按顶部素材栏方案完成本地实现及下述验证；未提交。

## 要解决的问题

目前审查分镜提示词时，人物、环境、道具、声音资产只显示 `{{Mixed N}}` 和文字描述。审查者需要离开提示词找素材，难以直接核对人物造型、场景角度、道具状态与音色。

目标是在同一个预览上下文里完成“读描述 → 看参考图／试听声音 → 回到原位置”。截图中的 EP24 U101 作为首个验收样例；功能按项目通用能力设计。

本文件属于仓库产品设计文档。交互草图是本次会话的说明材料；不属于短剧正式素材，不写入故事或素材索引。

## 推荐界面

采用“顶部素材栏 + 正文可点引用 + 独立媒体查看层”。沿用当前浅色／深色主题与文件预览框架，不另加常驻右侧栏。

1. 在阅读工具栏下、正文之前增加“引用素材 5 项”区域。卡片按该单元 `Mixed` 顺序排列，显示约 64–80px 的图片、编号、名称和类型；状态与版本在详情显示。人物标准图按完整比例 `contain` 展示，避免四视图裁切。
2. 素材较多时折叠多余卡片，提供“展开全部”；窄屏采用两至三列换行。用户可收起整栏，正文仍能点击引用。素材栏初版随文档滚动，避免与现有悬浮工具栏争抢纵向空间。
3. `{{Mixed N}}` 在正文渲染为带图片／声音图标的可点标签。顶部与正文共用同一份引用映射。通过 Markdown 语法树或受控文本节点渲染，跳过代码块与已有链接，不用正则替换整个 Markdown 源文件。标签保留原占位符文本，避免选择复制时丢失花括号。
4. 图片点击后在当前提示词上方打开大图，显示名称、编号、版本、素材状态。可查看完整图及原尺寸细节；关闭回到原阅读位置和触发按钮。
   点击外侧遮罩或按 Esc 只关闭当前层：先关闭大图／试听，回到提示词；再次点击提示词外侧遮罩才关闭文件预览。点击内容区或从内容区拖到外侧不关闭。
5. 音频点击后展开一个紧凑播放器，提供播放／暂停、进度拖动和时长。点击另一个声音自动停止上一条；切换提示词、关闭预览或离开页面时停止并释放媒体。默认不自动播放、不批量下载音频或生成波形。
6. 素材状态照实展示。`DRAFT` 可以看图审查，`ACCEPTED` 表示原有验收状态，打开或试听本身不改变状态；引用解析成功也不代表已上传或已接入 LibTV。

备选“随文素材卡”：把缩略图直接放在每段资产描述旁，图文关系更紧密，但重复占用正文空间，长提示词会明显变长。建议首期采用顶部栏，备选用于比较，不同时实现两套布局。

2026-10-20 用户选择“顶部素材栏”，并要求点击阴影关闭弹窗。实现对共用 Markdown 预览生效，覆盖剧本视图与素材文件视图；图片和声音统一使用独立查看层。声音卡被用户点击后尝试播放，失败时保留手动播放入口，不在打开提示词时播放。

## 已核实的数据基础

- 当前实际工作区为仓库内 `workspace/`，无 `.env.local` 覆盖。
- EP24 当前提示词 `EP24-S01-U101-VIDEO-SHOT-PROMPT-v04.md` 已正式绑定；页面使用 `DOCUMENT:2542` 这样的合成 ID，不能把它直接当成正式资产 ID。
- 正式 `EP24-REFERENCE-PLAN-v06.json` 的单元已有 `bodyPath + bodySha256 + referencePlan.assets[]`，足够精确关联提示词、Mixed 编号和素材。
- U101 顺序为：1 狗仔甲标准图、2 霍景深标准图、3 门外对街场景、4 完整摄像机、5 狗仔甲固定音色（4.23 秒）。引用计划中的四张图为 `DRAFT`，声音为 `ACCEPTED`。
- `StoryAssetLink` 目前只描述素材，没有提示词与引用计划的关联。现有 Markdown 预览只认识 Markdown 图片与链接，不解析 Mixed 引用。
- 目前媒体地址由 `/api/projects/:id/file?path=...` 提供，`path` 以 `library/` 为根；正式计划中的路径包含 `library/`，需要在服务端明确归一化。

## 最小数据链路

增加一个按需、只读接口：

```text
GET /api/projects/:projectId/prompt-references?path=<library 根相对提示词路径>
```

不增加素材 schema，不往 Markdown 写图片链接，不读取 LibTV 远端来决定本地引用。打开支持的提示词时才请求，普通剧本或说明文档保持原样。

服务端流程：

1. 校验请求路径，读取指定提示词及其正式业务归属。
2. 只从正式绑定、角色为 `reference-plan` 的本地文档寻找相关计划；不按目录里最大版本号选文件。
3. 通过精确稿件路径与正文哈希找到单元，提取该单元引用。存在多个冲突匹配时返回冲突，不任取一个。
4. 用 `assetId + path + sha256` 核对正式素材与文件；继承现有项目边界、符号链接和路径检查。按所引用的确切版本解析，不自动替换为当前同名资产。
5. 返回引用顺序、名称、媒体类型、版本、素材状态、用途、音频时长、文件地址及解析结果，附引用计划来源，便于定位问题。必要的哈希读取可按文件变化缓存，避免切稿反复扫描全项目。

建议的独立读模型：

```ts
interface PromptReferencePreview {
  promptPath: string;
  unitId?: string;
  sourcePlanPath?: string;
  state: "RESOLVED" | "UNAVAILABLE" | "CONFLICT";
  references: Array<{
    reference: string;
    label: string;
    assetId?: string;
    kind: "image" | "audio" | "video" | "other";
    version?: string;
    assetStatus?: string;
    responsibility?: string;
    durationSeconds?: number;
    url?: string;
    resolution: "RESOLVED" | "UNREGISTERED" | "MISSING_FILE"
      | "VERSION_MISMATCH" | "UNSUPPORTED" | "CONFLICT";
    reason?: string;
  }>;
}
```

解析状态与素材验收状态分开；不可播放项不给有效媒体 URL，但保留编号和原因。首期提供图片与音频交互，其他类型显示明确说明。

## 兼容与降级

- 首期覆盖当前 EP22–EP25 使用的单元结构，并根据真实样例支持明确的 `bodyPath / promptPath` 别名。现有约 21 个当前引用计划的字段并不统一，不能宣称一次覆盖所有历史格式。
- 历史稿找不到匹配计划，显示“此版本尚未关联引用素材”；正文正常阅读。绝不靠人物名、镜头编号或全文 `Mixed 1` 猜图。
- 合并文档中不同单元可能复用同一个 Mixed 编号。没有可靠单元边界时保持未解析，后续再增加分段适配。
- 文件缺失、哈希不一致、跨项目路径、映射冲突分别提示原因。明确引用的历史／拒绝素材可以在可验证时带醒目标识供审查，不套用“当前素材图库”的过滤规则而静默消失。
- 快速连续切稿时取消旧请求，过期响应不能覆盖新稿的素材栏。

必须处理：

- `FilePreviewDialog` 已使用原生 `dialog.showModal()`。现有图片灯箱是 portal 到 body 的普通 div，不能靠更大 z-index 越过 dialog 的 top layer。查看层需要使用后打开的原生 dialog 或同等可靠的顶层管理；第一次 Esc 只关图片，第二次才关提示词，关闭后恢复焦点。
- 不能直接通过当前 `onOpenMaterial` 打开引用图，它会替换提示词或跳转文件视图。引用查看使用局部状态，保留原 URL、上下项和滚动位置。
- 现有 `AudioPreview` 挂载即下载整段并解码波形，不给每张声音卡挂载一份。使用单一播放器，用户点击才设置来源。
- 缩略尺寸与下载体积是两回事。首期可懒加载所选稿件图片、复用文件接口；大文件若导致明显等待，应补服务端缩略图缓存，不能把 CSS 缩小宣称为已优化下载。缓存是可重建运行数据，不新增正式素材。
- 当前普通文件接口未实现 Range。首期以真实短音频验证播放与拖动；若需要长音频可靠跳转，应补 Range 并验证 206/416，再扩大范围。

## 验收点

- EP24 U101 的 5 个引用顺序、图像、音频及版本全部对应正式计划；不混用其他镜头或最新同名图。
- 四视图缩略图完整可辨；点击能打开大图并查看细节，关闭后不丢阅读位置。
- 顶部卡片和正文同编号指向同一素材；搜索、章节定位、原占位符复制不被破坏。
- 未点击音频时无批量声音下载；试听可以暂停与拖动，同时最多一个声音播放；切稿、关闭或离开立即停止。
- Esc、Tab、焦点恢复和弹窗层级正确；不遮住关闭按钮，窄屏无横向页面溢出。
- URL 深链、浏览器返回、预览上／下项行为保持正确；引用局部预览不替换提示词。
- 缺文件、旧稿、哈希冲突与不支持格式明确降级，正文仍可读。
- 通过类型检查、相关 resolver/API 测试、现有应用测试及浏览器真实交互验证。浏览器窄屏验证单独记录，不声称是真机验收。
- 所有生产文件、正式索引和验收状态保持原值；该功能只增加审查能力。
