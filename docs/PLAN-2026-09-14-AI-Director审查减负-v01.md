**二、这次调整的原则**

1. 创作内容由主会话判断，文件一致性由工具处理，无法从文字确定的模型效果留到已授权试片观察。三者适用时机不同，不要求每个任务都经过三轮。
2. 默认交付用户需要的成果和真正待决的问题。已有记录能表达的事实，不再建立另一份表格、合同或审查报告。
3. 只因具体问题扩大检查范围。没有新证据，不因为换任务、角色名、版本号或恢复执行而重新证明整部作品正确。
4. 完成当前授权范围即交付。后续阶段尚未发生，不影响如实报告当前文本或素材工作已完成。
5. 保留用户明确的创作与生产要求。减负不自动取消多镜头、逐字对白、完整中文、全名、项目自包含、本地正式更新、运行前回读和真实媒体检查。

**三、优先调整 AI Director 和规则入口**

**P0-1：把审查规则集中到一个短入口，移出默认加载的详细评分。**

以现有 review-mode.md 为默认判断入口。主 Skill 只说明何时使用、什么时候可结束；workflow-contract 只说明来源、复用、执行和恢复；角色文件只说明创作职责；知识库保留方法与实例。删除重复正文，改为精确引用，不在多处分别维护同一份硬伤清单。

把十四维详细评分、特定十五秒档案和长案例说明从默认审查阅读路径拆为按需参考。用户要求评分时仍能找到；普通创作无需把可选评分表完整读进上下文。保留既有链接或重定向说明，不删除历史材料，不新建知识注册系统。

默认阅读随问题发生：普通双人对话主要读对白和反应方法；跨门或递接才读对应空间与归属方法；屏幕插镜才读可读信息分工。新建整场仍要有完整导演思考，局部修复不强制重读全部专项文档。

同一有效上下文中，已读且未变化的方法无需重读。上下文丢失时，从当前对象、简短结论和相关段落恢复；确有缺失再补读。恢复依据不足时检查缺失部分，不用“已经读过”掩盖不确定性。

涉及文件：AGENTS.md 中审查相关段落、AI Director 主文件、workflow-contract.md、review-mode.md、director-role.md、分镜知识 README 和《分镜提示词生产与交付前审查》。具体创作方法正文只在确有重复规则时调整。

**P0-2：让检查发生在写作收尾，避免登记后才发现机械问题。**

主会话完成正文时，先处理名字、对白、镜头格式、计时和声明引用，再结合最终通读检查实际剧情与执行冲突。这些合为一次创作收尾，不分别扮演作者、Reviewer、Coordinator 各读一遍。

真正需要人判断的内容集中在：是否改变已确认剧情或台词；动作、空间、人物和参考能否同时成立；观众能否接收到必要信息；表演时间是否明显装不下；是否违反当前用户硬要求和真实入口限制。其它方法用于提高创作质量，不逐项要求写“通过证明”。

全名检查在正式绑定前完成。保留全名规则，疑似“自己／对方”等用法由主会话结合句义处理；不对自然对白、引用原文做全局替换。一次性整理当前授权范围内的索引变更，再完成正式登记和适用的回读，减少刚发布即联动升版。

已保存旧稿继续保留；该建议不允许覆盖版本，也不允许跳过本地先于 LibTV 的现行顺序。用户要求分阶段交付时，各阶段仍按要求交付；“一次性整理”仅指该次明确交付范围，不要求先完成全剧。

**P0-3：减少必须单独维护的文档，把专业思考与文书数量分开。**

Task Packet 改成当前记录中的简短上下文，不要求每个任务新建 JSON 或填写无关字段。授权来自用户指令，记录负责保存授权范围，不能因为少填一个字段而产生第二次审批。

导演仍须先想清楚怎样拍，但普通单元可在写正文的同一轮完成设计，沿用执行表或已有设计说明；不要求另交一份 Director Design 才能开始正文。只有用户点名要导演设计，或复杂场面确实需要比较与固定方案时，才把设计作为独立成果。

当前正文、正式引用和索引继续作为事实源。总览主要链接当前成果，避免在多份总览、计划和项目说明里手工重复路径、镜头数、状态与“下一步”。可从正式数据导出的信息逐步由工具或页面生成；既有文件保留，在下一次正常修改时减少重复字段，不开展全工作区迁移。

检查结论复用已有记录：写清本次范围、具体问题或无硬伤、修复和下一步即可。问题多时可以详细解释；没有问题时，不为每个镜头生成逐项证明。

**P0-4：阻塞只影响它真正阻止的动作，结论不再把所有未来事项一起压给用户。**

下面是判断方法，不新增数据库状态或强制表单：

| 发现 | 对当前工作的处理 |
| --- | --- |
| 已确认台词被改、人物动作主体错误、参考造型明显冲突、当前模型确实不支持输入 | 修受影响部分；无法就地解决时说明具体阻止哪次执行，其它已授权工作继续 |
| 无法从提示词判断袖口灰痕是否稳定、表演是否自然、细字能否在视频保持 | 记录待试片观察；没有明确冲突时不靠反复扩写提示词寻求保证，试片仍须已有生成授权 |
| 用户已暂缓声音、尚未取得未来连续性帧或 Node ID | 说明后续何时需要，不拒绝当前文本设计；真正使用这些输入时再核验是否就绪 |
| 文件或索引未同步 | 由执行操作修复和回读；不据此重开剧情或导演评审 |
| 更理想的推镜、停顿、表情或构图 | 作为可选建议，不自动返修、不追加生成、不阻止交付 |

“待人工确认”保持真实，但不自动解释为每个阶段都要停下来问一次。是否等待取决于用户是否要求先确认该成果，以及下一步是否依赖尚未给出的决定。最终人工采用、用户指定的选音/代表性试片确认及新增花费边界继续保留。

用户界面和回复默认表达：这次完成了什么；有哪些会影响用户决定的问题；接下来能做什么。详细路径、哈希、接口检查和历史证据留在来源中，不让用户承担内部核对工作。

**四、再补一个小工具入口，承担已有的机械检查**

P0 规则改完并用下述样例走通后，再判断剩余机械负担。确有收益时，提供一个薄的公共检查入口，复用现有校验器和 story catalog。它读取本次目标文件与相关正式绑定，输出可定位的差异和错误；不创建工作流引擎，不要求先注册任务才能运行。

优先覆盖：

- v2 镜头块、连续计时、声明引用：复用现有 [validate-shot-prompt.mjs](/Users/zhangboxuan/dev/demos/drama-material-center/.agents/skills/doubao-creative-studio/scripts/validate-shot-prompt.mjs:11)，保留旧入口兼容。
- 逐字对白、当前路径与哈希、拒绝素材引用、模型确定性限制：复用已存在的正式来源与相关校验，补足当前需要的适配。对白归属和自然语言代称有歧义时提示主会话判断，不冒充确定性结论。
- 正式登记前列出本次应一起更新的直接引用，避免页面回读后才发现另一份当前总览仍指旧版；没有实际引用关系的文档不联动。
- 沿用现有登记与回读能力，把重复脚本提炼成可复用函数。涉及正式写入的工具另做小范围可恢复设计，旧版本保留；不把构建完整事务系统作为本轮减负前提。

文字、素材引用和模型参数发生实质变化时，主会话仍检查受影响内容。脚本不生成导演正文、不判定表演自然度、不把哈希一致当作媒体验收，也不自动提交付费任务。

**五、网站调整列为后续小项**

本轮主要收益可以由 Skill 和知识入口调整获得，网站不作为前置条件。后续只解决当前发现的阅读负担：

- 在现有分集页突出当前成果、真正阻塞当前动作的问题和用户明确暂缓的事项；生成候选、文本已检查、媒体已查看、人工采用分别保持原有含义。
- 根据稳定资产 ID 展示当前版本与变化说明，旧版证据折叠；不要求用户逐份确认执行表、素材计划、引用 JSON 和检查记录。
- 修正上一轮调研发现的分镜进度统计口径及“成片与声音”混入其它文档的问题。改动范围限现有视图，不做画布、聊天界面或新的生产看板。

Toonflow 值得吸收的类型、画风和具体镜头方法，放在减负验证后，按现有项目真正遇到的问题补入知识库。每次补方法同时检查是否可以替换旧的冗余说明，不增加一个默认必读层。

**六、怎样确认减负有效，并且没有漏掉必要问题**

先用冻结文本与已有记录做离线回放，不新增生图或视频花费，不改当前项目正式绑定。样例用于比较改动前后行为，不再给日常创作增加一套评分流程。

| 样例 | 调整后应出现的行为 |
| --- | --- |
| 《纯手工代码》屏幕修订恢复 | 能区分 17 段未完成接入修订、其中 4 段再次修改和其余 14 段已有有效结果；拒绝图仍排除，声音暂缓仍保留；在当前交付内同步直接相关总览，不重新设计整集 |
| EP13 四条代称修复 | 保留全名要求；在首次正式登记前找出疑似项，只检查修改句及受影响关系；自然对白不被机械替换，不重审其它 9 条提示词 |
| 已检查提示词替换同一资产的 Mixed／Node 编号 | 检查映射、正文等价、真实引用与入边；不做第二轮导演设计和评分；运行前回读继续执行 |
| 一个具体硬伤与一个审美建议并存 | 错说话人、错误输入或无法成立的跨门动作仍被发现并修复；更理想的停顿与运镜不会变成附加返修任务 |
| 只请求分镜文字，后续声音/视频未生成 | 完成文字和适用的本地接入，明确后续条件；不会伪报视频已验收，也不会为证明文本可行额外生成音频 |
| 用户接受当前候选后出现可选精修建议 | 在确认用途内继续采用，停止可选返修；只对新出现、有具体位置与影响的硬伤重新提出问题 |

比较这些可观察结果：重复读取未变方法的次数；本次额外维护的文档与临时脚本；没有新问题依据的完整重审；额外要求用户回复“继续”的次数；明确用户要求是否遗漏；实际缺陷是否仍能定位。

不以固定分钟数、文档长度、检查轮数硬上限或“必须一次通过”作为制作门槛。复杂的新稿需要完整阅读，新的真实问题也需要修复；目标是去掉无信息增量的工作。若样例证明某项精简漏掉明确硬伤，只恢复相应检查，不恢复整套重流程。
