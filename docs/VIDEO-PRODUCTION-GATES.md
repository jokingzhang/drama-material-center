# 视频生产前门禁

这份文档说明仓库 Harness 的执行接口，不存放真实项目资料。规则来源是 [AGENTS.md](../AGENTS.md) 与 [制作 SOP](../PRODUCTION_SOP.md)：每剧锁定画幅，确认剧本后确认台词，再设计分镜。门禁在创建及付费运行之前执行，不以生成后的返工代替预防。

## 1. 每部剧的画幅

在项目 `PRODUCTION_RULES.md` 中保留唯一的机器段落。示例值仅解释字段，不能替项目选择方向：

```json
{
  "locked": true,
  "orientation": "portrait",
  "aspectRatio": "9:16",
  "timelineWidth": 1080,
  "timelineHeight": 1920,
  "canvasIds": [],
  "authority": "真实用户决定的出处及内容"
}
```

上面的 JSON 代码块紧跟 `<!-- VIDEO_FORMAT_LOCK -->`。横屏使用 `landscape / 16:9` 及相同比例的时间线尺寸。画布未创建时允许空 `canvasIds`；创建视频节点前必须加入已核实属于本剧的画布 ID。

没有锁、重复或矛盾的锁、错误方向、正文冲突、任务画布不属于本剧，都停止。创建比例从项目锁派生；运行前还会读取节点实际参数。某次任务说反方向不能更新锁，只有明确改变整部剧标准的指令才可更新。封面、场景母版的横图不决定视频画幅。

## 2. 已确认台词是唯一来源

继续使用 `contract.dialogue` 的标准目录、正式绑定和 Markdown 台词表，不建立第二套对白台账。表格识别这些列名：

| 字段 | 支持的表头 |
| --- | --- |
| 稳定台词 ID | `ID`、`对白ID`、`台词ID` |
| 归属 | `说话者`、`说话人` |
| 原句 | `逐字对白`、`逐字台词`、`逐字正文` |

说话人中的声源标注一并保留，例如 `霍景深（电话）`。句内标点、重复、停顿、引号均属于原文，校验时不近义替换或模糊归一化。其它既有意图、时间、听者反应等列保留。

确认剧本、确认台词后，在该合同中登记以下机器段落；`units` 是分镜完成后补入的单元映射，不要求在设计分镜前就知道镜头编号：

```text
<!-- DIALOGUE_LOCK -->
```

标记后紧跟 JSON 代码块，内容结构如下：

```json
{
  "script": {
    "assetId": "当前分集剧本的稳定资产ID",
    "sha256": "当前确认剧本的文件SHA-256",
    "confirmation": {
      "confirmed": true,
      "source": "真实用户确认消息的定位",
      "quote": "用户确认剧本的原话"
    }
  },
  "confirmation": {
    "confirmed": true,
    "source": "真实用户确认消息的定位",
    "quote": "用户确认台词的原话"
  },
  "units": {
    "EP01-S01-U01": ["D01", "D02"],
    "EP01-S01-U02": []
  }
}
```

- `units` 按剧情顺序完整覆盖合同的台词 ID；无对白的单元明确写空数组，不能把漏配误判为静音。整份合同确实无对白时，正文写 `本范围无对白`，仍绑定已确认剧本。
- 剧本与合同必须来自同集当前正式绑定；源文件、正式索引与任务中的 SHA-256 相符，不能随意指向历史草稿。合同原句必须存在于确认剧本。
- 同一条用户消息可以确认剧本及台词；旧确认可直接复用，补登记不需要重新询问。不得伪造确认、将作者自检写成用户决定，或因为文件已被登记就自动填 `confirmed: true`。程序校验记录和字节一致性，无法自行认证聊天中的真实授权；Agent 必须如实恢复来源。
- 设计镜头或返工时只补执行信息，不改确认原句。需要改词时，先取得用户明确指令，更新剧本及合同的新版本，确认新台词，然后更新受影响分镜。不得通过同时改合同、任务和索引来绕过授权。

## 3. 提示词和执行任务

模型正文仍使用既有三字段镜头格式。在连续画面叙述中，以可确定归属的方式引用原句，例如：

```text
江砚秋按住方案纸，抬眼看向窗外。江砚秋：“我自己决定。”
电话传来答复，江砚秋倾听。霍景深（电话）：“好，等你答复。”
```

台词只出现一次；在说话人和冒号之间不插入动作或改写声源标注。动作、表情和声音处理放在相邻叙述。支持中文双引号、直角引号及成对英文双引号，保留句内嵌套引号。真实画面可读文字可用 `画面文字：“……”` 或 `书面文字：“……”` 明确归属；不能拿这些标签隐藏口头对白。其它含糊引号会被拒绝，避免将新台词当作装饰文字漏过。不要在正文中另写未标注的新增对白、暗示模型即兴说词或改义转述。

这只是可机械提取的说话归属，不新增镜头字段，不要求一句一个镜头或一个节点，也不允许因此改句子。旧稿在下次受影响生产时做等价归属标记及版本化登记；已有文件、可用媒体和未执行的其它项目不批量改写或重生成。

现有视频任务 JSON 加入：

```json
{
  "dialogueLock": {
    "assetId": "当前合同的稳定资产ID",
    "sha256": "正式合同文件SHA-256",
    "unitId": "EP01-S01-U01"
  }
}
```

任务的其它参数仍沿用现有 `promptPath / promptSha256 / projectUuid / mediaNodeIds / localPublicationVerified` 及节点设置。合同、剧本和提示词的新版本都先正式登记；哈希来自实际文件，不能填示例值。

## 4. 唯一视频执行入口

```sh
python3 scripts/video-format-gate.py check --project-dir <项目目录> --task <项目内任务JSON>
python3 scripts/video-format-gate.py create --project-dir <项目目录> --task <项目内任务JSON>
python3 scripts/video-format-gate.py run --project-dir <项目目录> --task <项目内任务JSON>
```

`check` 只做本地检查，不调用 LibTV；同步文字/视频正文前先执行它。`create` 在全部本地门禁通过后才调用官方 CLI。`run` 重做本地门禁，回读文字节点、视频节点和引用，再提交。所有动作均要求独立满足原有授权边界；检查通过不授予生成或消费积分的权限。

缺失台词锁、未确认、哈希过期、加词、删词、换词、换说话人、换顺序、漏单元以及画幅错误均会阻断。禁止绕开包装器直接运行视频 CLI，禁止错误后静默回退到无门禁脚本。无对白单元也不能省略对白锁。

只修画面时默认复用已有可用原声，并在原有执行记录注明源文件/版本、哈希和覆盖范围；音色参考不等于原声对白。确需新生成声音时仍锁定原句。门禁能防止已知的错误输入，不能保证模型输出逐字正确，也不替代已有视听验收规则。

## 5. 无积分回归验证

```sh
npm run test:video-format
npm run test:dialogue-gate
```

测试使用临时虚构项目、临时合同和模拟 CLI，不访问真实画布、不运行生成、不修改项目素材。覆盖双向画幅锁、错误输入在创建/运行前阻断、缺对白锁、原句/说话人/顺序变化和确认来源缺失等情况。
